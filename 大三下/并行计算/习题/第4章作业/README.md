## 问题原因总结

我的错误在于：**把题目中的 `flag` 变量理解成了“资源占有标志”，而实际上它表示“轮到哪个线程执行”**

我原来的理解类似于：

```c
flag0 = 1; // 线程占有资源 0
flag1 = 1; // 线程占有资源 1
```

因此我认为可能出现：

- 线程 0 占有资源 0，等待资源 1
- 线程 1 占有资源 1，等待资源 0
- 两个线程互相等待，形成无限忙等待

但题目中的代码是：

```c
while (flag0 != my_rank);
while (flag1 != my_rank);
```

这里的 flag0 和 flag1 并不表示资源是否被占有，而是表示：

**当前允许哪个线程继续执行**。

因此它们的作用更接近于 执行顺序控制变量，而不是互斥锁。

如果初始值为：
flag0 = 0;

flag1 = 0;

那么线程 0 可以先通过两个 while 检查，进入临界区；线程 1 则会被阻塞在忙等待中。等线程 0 执行完临界区后，修改 flag0 和 flag1，线程 1 才能继续执行。

所以这个 busy-wait 版本不会产生互相占有、互相等待的问题，因为它没有让两个线程分别占有不同资源，而是直接强制规定了进入临界区的顺序。
