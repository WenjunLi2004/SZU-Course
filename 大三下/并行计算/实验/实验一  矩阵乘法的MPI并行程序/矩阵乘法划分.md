## 1. 行/列块划分 1D
**经典划分方法**：A数组行 or  B数组列划分给不同进程，另外一个数组Bcast给全体进程，各自执行完再Gather

**优点：划分简单**

**缺点：**
1. **进程数 $p$ 永远不能超过矩阵的维度 $N$**：如果你有 2000 个核心，但矩阵只有 1000 行，那剩下 1000 个核心只能干瞪眼，完全无法参与计算

>著名的几何定理：**计算量与块的“面积”成正比，而通信量与块的“周长”成正比。**

2. 每个核心分到的**块大小**是 $\frac{N}{p} \times N$，周长大约是 $2N$：意味着每个核心在通信时，要发送/接收的数据量级别是 **$O(N)$** ，哪怕 $p$ 再大，通信量也很难降下来
## 2. 棋盘划分 2D
把进程排列成一个 $\sqrt{p} \times \sqrt{p}$ 的二维网格，具体划分步骤：
1. **进程网格化**：将 $p$ 个进程排列成 $q$ 行 $q$ 列的网格，每个进程可以用它的二维坐标 $P_{i,j}$ 来表示（$0 \le i < q$，$0 \le j < q$）
2. **矩阵分块**：进程 $P_{i,j}$ 初始时只负责存储矩阵 $A$ 的子块 $A_{i,j}$ 和矩阵 $B$ 的子块 $B_{i,j}$，最终的目标是计算出矩阵 $C$ 的子块 $C_{i,j}$
3. **==通信过程==（多到多播送）**：计算 $C_{i,j} = \sum_{k=0}^{q-1} (A_{i,k} \times B_{k,j})$，这意味着进程 $P_{i,j}$ 需要它所在**行**的所有 $A$ 子块，以及所在**列**的所有 $B$ 子块
	- **行通信**：网格中第 $i$ 行的所有进程（共 $q$ 个）进行一次多到多广播（`MPI_Allgather`）。这样，第 $i$ 行的每个进程都能收集到完整的第 $i$ 行 $A$ 矩阵的数据（即 $A_{i,0}, A_{i,1}, ..., A_{i,q-1}$）
	- **列通信**：网格中第 $j$ 列的所有进程（共 $q$ 个）进行一次多到多广播。这样，第 $j$ 列的每个进程都能收集到完整的第 $j$ 列 $B$ 矩阵的数据（即 $B_{0,j}, B_{1,j}, ..., B_{q-1,j}$）

![[Pasted image 20260329203422.png#pic_center|330]]

- **极限：** 最多可以切出 $N \times N$ 个小方块！也就是说，**进程数 $p$ 可以高达 $N^2$** 同样是 $1000 \times 1000$ 的矩阵
- **通信（正方形形状）**：每个核心分到的块大小是 $\frac{N}{\sqrt{p}} \times \frac{N}{\sqrt{p}}$，它的周长是 $4 \times \frac{N}{\sqrt{p}}$，通信量级别变成了 **$O(\frac{N}{\sqrt{p}})$** ，**棋盘划分极大地压缩了网络通信的数据量**

**缺点：**
1. 划分方式比较复杂，需要同时对两个矩阵进行划分
2. **存储较大**：需要开辟额外空间来接收**A行块和B列块**，总大小为 $n^2 / p$ 

**==代码思想==：**
1. **并行 I/O**：数据存在分布式文件系统中，每个进程直接根据自己的编号去硬盘里读取**属于自己的那一小块**数据，大家同时读，没有任何进程需要拥有全局数据
2.  **`Allgather` 拼凑数据**：**MPI_Comm_split** 行和列分割 来减少通信开销
	- **重点**：MPI 的拼接方式就是简单粗暴地“首尾相接”，**增加一个offset来读取数据**`offset = x * m * m`

## 3. Connon乘法
**Motivation**：每个进程为了算自己的那一小块 $C$，必须把**一整行 $A$ 和一整列 $B$** 都收集到自己手里 —— 如果矩阵非常巨大，单节点的内存会被直接撑爆

**Cannon思想：数据流动起来，用完就传给下一个人**
- 每个进程手里永远只需要保存 **1 块 $A$** 和 **1 块 $B$**
- 我算完了，就把 $A$ 传给左边的邻居，把 $B$ 传给上面的邻居；同时接收右边和下面邻居传来的新块，这样内存消耗降到了最低

### 算法原理精讲（图解四个步骤）
假设我们有一个 $3 \times 3$ 的进程网格（$q=3$）。进程 $P_{i,j}$ 初始时拥有 $A_{i,j}$ 和 $B_{i,j}$
![[Pasted image 20260329220708.png]]
#### **步骤 ①：初始对齐（最神奇的一步）**

为了保证每一次乘法的两个矩阵块能够“==**对得上号**==”（即 $A$ 的列号等于 $B$ 的行号），必须先打乱初始阵型：

- **$A$ 矩阵按行左移 $i$ 步**：
     
    - 第 0 行不移
        
    - 第 1 行整体向左循环移 1 步
        
    - 第 2 行整体向左循环移 2 步
![[Pasted image 20260329220759.png|800]]
- **$B$ 矩阵按列上移 $j$ 步**：
    
    - 第 0 列不移。 
        
    - 第 1 列整体向上循环移 1 步 
        
    - 第 2 列整体向上循环移 2 步
![[Pasted image 20260329220915.png]]
 **💡 这一步的魔法在哪里？**

你看进程 $P_{1,1}$，初始它有 $A_{1,1}$ 和 $B_{1,1}$
 
初始对齐后：第 1 行的 $A$ 左移了 1 步，$A_{1,2}$ 转到了它的手里；第 1 列的 $B$ 上移了 1 步，$B_{2,1}$ 转到了它的手里

此时它手里拿着的是 $A_{1,2}$ 和 $B_{2,1}$。注意看下标！**2 和 2 对上了！** 这意味着它们俩相乘是合法的，且正是计算 $C_{1,1}$ 所需要的部分结果

#### **步骤 ②：乘加运算**

所有进程低头算账，每个进程把此时此刻捏在手里的 $A$ 块和 $B$ 块进行标准的矩阵乘法，并累加到自己的 $C$ 块中

![[Pasted image 20260329220951.png]] 
#### **步骤 ③：单步循环移位（数据流动）**

**算完一次后，大家开始传递数据**：

- 所有进程把手里的 **$A$ 块向左**传给邻居（最左边的传给最右边）
![[Pasted image 20260329221225.png]]
- 所有进程把手里的 **$B$ 块向上**传给邻居（最上面的传给最下面）
![[Pasted image 20260329221249.png]]
#### **步骤 ④：循环**

不断重复步骤 ② 和步骤 ③，**一共执行 $q-1$ 次**（在 $3 \times 3$ 的网格里，也就是再执行 2 次）

当数据绕场一周后，每个进程刚好拿到了计算自己那个 $C$ 块所需的所有数据，计算完美结束


### **Cannon 算法的优势总结**

- **极致省内存**：无论网格划分得多细，每个进程只需要 $O(m^2)$ 的内存，完全没有了上一节中拼接大数组的苦恼
    
- **通信无拥堵**：不需要像 `Allgather` 那样一对多广播，Cannon 算法里全都是**点对点通信**（Point-to-Point，只跟邻居说话），网络带宽利用率极高


### **MPI_Sendrecv补充**
普通的 Send 和 Recv 死锁危机，禁止相互同时发送
- 解决方案：`MPI_Sendrecv` 
- 作用：告诉底层 MPI 系统：“**我现在既要发数据给 A，又要从 B 收数据，请你帮我在底层统筹安排，保证安全，绝对不能卡死。**”
```c
	MPI_Sendrecv(
	    发送缓冲区首地址, 发送数量, 发送数据类型, 目标进程号(dest), 发送标签(tag),
	    接收缓冲区首地址, 接收数量, 接收数据类型, 源进程号(source), 接收标签(tag),
	    通信域(comm), 状态对象(&status)
	);
```
参数很多，但其实就是把 `Send` 和 `Recv` 的参数拼在了一起
- 底层需要**两个缓冲区**分别 存旧矩阵 和 接收新矩阵

==**更狠的进阶版**==：**`MPI_Sendrecv_replace`（就地替换）**
这个函数只需要**一个**缓冲区。它会把你指定的数组里的数据发出去，然后**直接用接收到的新数据覆盖掉这个数组**
```c
MPI_Sendrecv_replace(
    void *buf,              // 唯一的数据缓冲区（比如你的 a 矩阵）
    int count,              // 数量 (比如 m * m)
    MPI_Datatype datatype,  // 数据类型 (MPI_DOUBLE)
    int dest,               // 发给谁
    int sendtag,            // 发送标签 (一般写 0)
    int source,             // 从谁那接收
    int recvtag,            // 接收标签 (一般写 0)
    MPI_Comm comm,          // 通信域 (MPI_COMM_WORLD)
    MPI_Status *status      // 状态 (如果不关心可以填 MPI_STATUS_IGNORE)
);
```
