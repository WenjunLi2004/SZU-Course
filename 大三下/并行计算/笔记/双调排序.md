
> [!summary]+ 核心结论
> **双调排序的本质不是“寻找最小值”，而是预先规定一张固定的比较交换网络。**  
> 每一阶段都把数据划分为互不冲突的比较对，同一阶段可以并行执行；阶段之间存在数据依赖，必须同步。它牺牲部分比较次数，换取规则、易并行、分支少的结构。

## 1. 从串行排序过渡到排序网络

普通排序算法通常会根据数据内容动态决定下一步：快速排序选择主元并划分，归并排序递归拆分后合并，冒泡排序逐轮检查相邻元素

**这些方法在 CPU 上自然，但在 GPU 上可能产生递归、负载不均衡和分支发散**

双调排序反过来：

> **不根据数据决定“比较谁”，而是提前固定每一轮的比较对象和方向**

因此它属于 **排序网络（sorting network）**：

```text
输入
↓
固定的比较交换层 1
↓
固定的比较交换层 2
↓
……
↓
有序输出
```

**无论输入是什么，网络结构都不变**

## 2. 唯一基本操作：Compare–Exchange

```c
if (ascending) {
    if (a[i] > a[j])
        swap(a[i], a[j]);
} else {
    if (a[i] < a[j])
        swap(a[i], a[j]);
}
```

升序比较交换：

```text
左边保存 min(x,y)
右边保存 max(x,y)
```

降序比较交换恰好相反

> [!important]+ 最小并行任务
> **一个线程并不是负责“排序整个数组”，而是负责一对元素的一次比较交换**

固定阶段中，如果配对为：

```text
(0,4) (1,5) (2,6) (3,7)
```

这些配对互不重叠，因此可以同时执行

> 有点像奇偶并行交换

---

## 3. 什么是双调序列

双调序列满足下列任一形式：

1. 先递增，再递减；
2. 先递减，再递增；
3. 上述序列循环移位后的结果

例如：

```text
1, 3, 7, 9, 8, 6, 4, 2
↑ 递增       ↓ 递减
```

它还不是最终有序序列，但==**只改变一次单调方向**==，具有适合规则归并的结构

```text
任意序列
↓ 构造
双调序列
↓ 双调归并
单调有序序列
```

---

## 4. 双调归并的本质

假设长度为 `n` 的序列已经是双调的，并希望最终升序

**第一轮把前半区和后半区一一配对：**

```text
(0, n/2)
(1, n/2+1)
……
(n/2-1, n-1)
```

每对执行升序 compare–exchange：较小值进入前半区，较大值进入后半区

第一轮后得到两个性质：

1. 前半区整体偏小，后半区整体偏大；
2. 两个半区各自仍然是双调序列

于是问题递归缩小：

```text
长度 n 的双调序列
↓ 一轮 n/2 对比较
两个长度 n/2 的双调序列
↓
四个长度 n/4 的双调序列
↓
……
```

> [!abstract]+ 本质
> 双调归并并非一次把每个元素放到最终位置，而是逐层把“小值群”和“大值群”分开，再对子区间重复同样操作。

## 5. 4 个元素：完整串行过程

设有：

```text
a0 a1 a2 a3
```

### 5.1 构造两个相反方向的长度 2 序列

```text
(a0,a1) 升序
(a2,a3) 降序
```

形成：

```text
小→大 | 大→小
```

整个长度 4 序列因此成为双调序列

### 5.2 跨半区比较

```text
(a0,a2)
(a1,a3)
```

较小值进入前半区，较大值进入后半区。

### 5.3 两个局部长度 2 归并

```text
(a0,a1)
(a2,a3)
```

最终得到：

```text
a0 ≤ a1 ≤ a2 ≤ a3
```

将其概括为：**先做两个 2 元素蝶式交换，再完成一个 4 元素蝶式交换**

---

## 6. 8 个元素：逐级扩大结构

长度 8 的排序不是直接完成，而是：

```text
长度 2
↓
长度 4
↓
长度 8
```

理解路线：

1. 四个 2 元素蝶式交换；
2. 两个 4 元素蝶式交换；
3. 一个 8 元素蝶式交换。

构造更大双调序列时，相邻子序列方向相反：

```text
前半段递增
后半段递减
```

随后再把整个长度 8 的双调序列归并成递增序列。

## 7. 串行双调排序标准循环

当 `n` 是 2 的幂时，常见实现：

```c
void bitonic_sort(float a[], int n) {
    for (int k = 2; k <= n; k <<= 1) {
        for (int j = k >> 1; j > 0; j >>= 1) {
            for (int i = 0; i < n; i++) {
                int partner = i ^ j;

                if (partner > i) {
                    bool ascending = ((i & k) == 0);

                    if ((ascending && a[i] > a[partner]) ||
                        (!ascending && a[i] < a[partner])) {
                        float tmp = a[i];
                        a[i] = a[partner];
                        a[partner] = tmp;
                    }
                }
            }
        }
    }
}
```

三个循环分别回答：

| 变量 | 作用 |
|---|---|
| `k` | 当前构造多大的双调结构：2、4、8、…、n |
| `j` | 本阶段比较距离：`k/2、k/4、…、1` |
| `i` | 当前元素编号 |
| `i ^ j` | 当前元素的比较伙伴 |

## 8. 关键点1：为什么配对使用 XOR

```c
partner = i ^ j;
```

`j` 是 2 的幂，与它异或会翻转编号中的某一位

### `j=4`

```text
000 ↔ 100   即 0 ↔ 4
001 ↔ 101   即 1 ↔ 5
010 ↔ 110   即 2 ↔ 6
011 ↔ 111   即 3 ↔ 7
```

得到：

```text
(0,4) (1,5) (2,6) (3,7)
```

### `j=2`

```text
(0,2) (1,3) (4,6) (5,7)
```

### `j=1`

```text
(0,1) (2,3) (4,5) (6,7)
```

> [!tip]+ 记忆
> XOR 不是随意的位运算技巧，它是在蝶式网络中快速找到“距离为 `j` 的比较伙伴”。

## 9. 关键点2：为什么只处理 `partner > i`

若 `i` 处理 `(i,partner)`，而 `partner` 又处理 `(partner,i)`，同一对会被重复处理，甚至产生写竞争。

```c
if (partner > i)
    compare_swap(...);
```

例如 `(0,4)`：

- `i=0` 时处理；
- `i=4` 时 partner 为 0，不处理。

这样每对元素只由一个任务负责。

课件实现则只启动 `n/2` 个线程，通过 `Insert_zero` 直接构造唯一配对，从源头避免重复。

## 10. 关键点3：升序和降序如何交替

```c
bool ascending = ((i & k) == 0);
```

在构造更大双调序列时，相邻子区间需要相反方向：

```text
一个子区间升序
相邻子区间降序
```

课件代码中的：

```c
my_elt1 & bf_sz
```

承担相同作用：根据当前元素编号和蝶式规模，决定比较方向

## 11. 串行版本已经包含并行结构

串行代码按顺序执行：

```text
某一 stage 的比较对 1
某一 stage 的比较对 2
某一 stage 的比较对 3
……
```

但同一 stage 的比较对互不冲突，本来就可以同时执行

> **串行双调排序不是另一种算法；它只是把排序网络中本可并行的比较器逐个执行。**

这就是从串行过渡到并行的关键。

## 12. 哪一层可以并行

观察三层循环：

```c
for (k ...)
    for (j ...)
        for (i ...)
            compare_exchange(...)
```

- 不同 `k` 之间有依赖，必须顺序；
- 同一 `k` 下不同 `j` 之间有依赖，必须顺序；
- 固定 `k`、固定 `j` 时，各比较对互不重叠，可以并行。

因此：

```text
外层 k：顺序
中层 j：顺序
内层比较对：并行
每个 j 阶段结束：同步
```

> [!important]+ 并行核心
> **同一阶段内可以并行，不同阶段之间必须同步。**

## 13. CUDA：一个线程负责一对元素

```c
__global__ void bitonic_stage(float a[], int n, int k, int j) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;

    if (i >= n)
        return;

    int partner = i ^ j;

    if (partner > i) {
        bool ascending = ((i & k) == 0);

        if ((ascending && a[i] > a[partner]) ||
            (!ascending && a[i] < a[partner])) {
            float tmp = a[i];
            a[i] = a[partner];
            a[partner] = tmp;
        }
    }
}
```

主机端：

```c
for (int k = 2; k <= n; k <<= 1) {
    for (int j = k >> 1; j > 0; j >>= 1) {
        bitonic_stage<<<blk_ct, th_per_blk>>>(a, n, k, j);
    }
}
cudaDeviceSynchronize();
```

同一 stream 中 kernel 按启动顺序执行，因此每次 kernel launch 可以作为一个全 grid 的阶段边界。

## 14. 为什么课件直接版本只用一个 block

课件形式：

```c
Pbitonic_sort<<<1, n / 2>>>(a, n);
```

kernel 内每个阶段后：

```c
__syncthreads();
```

`__syncthreads()` 只能同步同一个 block，因此所有线程必须在一个 block 内

当：

```text
n = 2048
线程数 = n/2 = 1024
```

恰好达到常见设备单 block 1024 线程上限

> [!warning]+ 扩展限制
> 数组更大、需要多个 block 时，`__syncthreads()` 不能完成全 grid 同步
> 常见方法是每个 stage 单独启动 kernel，或使用 Cooperative Groups。

## 15. `Insert_zero` 的本质

课件不是让所有 `i` 都计算 partner 后再判断 `partner > i`，而是只启动 `n/2` 个线程：

```c
my_elt1 = Insert_zero(th, which_bit);
my_elt2 = my_elt1 ^ stage;
```

`Insert_zero(th, which_bit)` 的作用：

> 在当前配对位插入一个 0，直接构造比较对中较低的一端。

随后异或翻转该位得到另一端。

例：翻转第 2 位：

```text
th=00 → 插0得到000 → partner=100
th=01 → 插0得到001 → partner=101
th=10 → 插0得到010 → partner=110
th=11 → 插0得到011 → partner=111
```

因此得到：

```text
(0,4) (1,5) (2,6) (3,7)
```

两种方式对比：

| 方法 | 思路 |
|---|---|
| 通用写法 | 所有 `i` 计算 partner，仅 `partner > i` 工作 |
| 课件写法 | 启动 `n/2` 个线程，直接构造唯一配对 |

## 16. `bf_sz` 与 `stage`

课件代码：

```c
for (bf_sz = 2; bf_sz <= n; bf_sz <<= 1)
    for (stage = bf_sz >> 1; stage > 0; stage >>= 1)
```

对应标准写法：

```text
bf_sz ↔ k
stage ↔ j
```

| 变量 | 意义 |
|---|---|
| `bf_sz` | 当前构造/归并的蝶式规模 |
| `stage` | 当前比较伙伴间距离 |

例如 `bf_sz=8`：

```text
stage=4：跨两个半区比较
stage=2：更小分区内比较
stage=1：相邻比较
```

每个 stage 后必须同步。

## 17. 每个线程处理 `2m` 个元素

课件扩展版本令：

```text
n = 2048m
```

因为单 block 线程数有限，**不再让每个线程只处理一对单元素**，而是：

```text
每个线程负责两个长度为 m 的子列表
总共处理 2m 个元素
```

流程：

1. 线程找到两个子列表；
2. `Compare_swap` 合并并按目标方向排序这 `2m` 个元素；
3. 当前阶段结束；
4. `__syncthreads()`；
5. 进入下一阶段。

这体现了并行算法中的**凝聚（agglomeration）**：线程数量受限时，把多个细粒度比较合并成一个较粗粒度任务。

## 18. 复杂度：总工作量与并行深度

设：

```text
n = 2^q
```

### 阶段数

第 1 个规模有 1 个 stage，第 2 个规模有 2 个，……，第 q 个有 q 个：

$$
1+2+\cdots+q=\frac{q(q+1)}{2}=O(\log^2 n)
$$

### 每阶段比较数

每阶段有：

$$
\frac{n}{2}
$$

对 compare–exchange。

### 总工作量

$$
O(n\log^2 n)
$$

### 理想并行深度

若每阶段的 `n/2` 个比较器都同时执行：

$$
O(\log^2 n)
$$

| 指标 | 复杂度 |
|---|---:|
| 总比较工作量 | $O(n\log^2 n)$ |
| 排序网络并行深度 | $O(\log^2 n)$ |
| 归并排序总工作量 | $O(n\log n)$ |

> [!important]+ 不要混淆
> 双调排序不是工作量最优，但并行结构高度规则。

## 19. 为什么适合 GPU

| 特征 | GPU 收益 |
|---|---|
| 比较伙伴由位运算确定 | 无需动态搜索 |
| 每阶段配对固定 | 容易映射线程 |
| 同阶段比较互不冲突 | 并行度高 |
| 各线程逻辑相似 | 分支发散较少 |
| 无递归动态任务树 | 控制流规则 |
| 阶段数可预测 | 易分析和同步 |

> [!abstract]+ 核心交换
> 双调排序用更多比较次数，换取了规则的并行结构。

## 20. 局限性

1. 通常要求 `n` 是 2 的幂；
2. 非 2 的幂时需要填充：升序可填 `+∞`；
3. 总比较次数为 $O(n\log^2 n)$；
4. 每个 stage 都需要同步；
5. 跨多个 block 时通常需要多次 kernel launch；
6. 频繁访问 global memory 时可能受带宽限制。

更适合：

- 固定长度、中小规模数组；
- 批量排序许多小数组；
- 数据能放进 shared memory；
- 需要规则、可预测执行时间；
- GPU 排序网络教学。

## 21. 与其他排序算法对比

| 算法 | 核心结构 | 总复杂度 | 并行特征 |
|---|---|---:|---|
| 奇偶交换排序 | 奇偶阶段相邻比较 | $O(n^2)$ | 每阶段约 `n/2` 对 |
| 归并排序 | 递归拆分 + 归并 | $O(n\log n)$ | 归并划分较复杂 |
| PSRS | 局部排序 + 采样 + 分桶 + 多路归并 | 依实现 | 负载均衡复杂 |
| 双调排序 | 固定蝶式比较网络 | $O(n\log^2 n)$ | 规则，适合 GPU |

## 22. 常见误区

> [!warning]+ 易错点
> 1. 双调序列不等于完全有序序列。
> 2. 一个蝶式阶段不能独立完成全部排序。
> 3. 同阶段可并行，跨阶段必须同步。
> 4. `partner = i ^ stage` 得到的是比较伙伴，不是随机下标。
> 5. 不做 `partner > i` 或唯一配对构造会重复处理同一对。
> 6. `__syncthreads()` 不能跨 block。
> 7. 总工作量 $O(n\log^2 n)$ 与并行深度 $O(\log^2 n)$ 不能混淆。

## 23. 期末答题模板

### 什么是双调排序？

> 双调排序是一种基于排序网络的比较排序算法。它先构造由递增段和递减段组成的双调序列，再通过固定的蝶式比较交换网络将双调序列归并为单调序列。比较对象和执行阶段与输入数据无关，因此结构规则，适合 SIMD/SIMT 并行执行。

### 为什么适合 GPU？

> 在每个阶段中，元素被划分为互不重叠的比较对，各比较对之间没有数据依赖，可以由不同 CUDA 线程并行完成。比较伙伴可由异或位运算确定，线程执行相似的 compare–exchange 操作，因此控制流规则、分支发散较少。

### `partner = i ^ stage` 的作用

> `stage` 是 2 的幂，与 `i` 异或会翻转对应二进制位，从而得到蝶式网络中距离为 `stage` 的比较伙伴。例如 `stage=4` 时得到 `(0,4)、(1,5)、(2,6)、(3,7)`。

### 为什么阶段之间需要同步？

> 同一阶段的比较对互不冲突，可以并行；下一阶段需要读取上一阶段比较交换后的结果，因此阶段之间存在数据依赖。单 block 时可使用 `__syncthreads()`，跨 block 时通常通过多次 kernel launch 实现全局阶段同步。

### 复杂度

> 对于 $n=2^q$，共有 $q(q+1)/2=O(\log^2n)$ 个阶段，每阶段执行 $n/2$ 次比较交换，因此总工作量为 $O(n\log^2n)$，理想并行深度为 $O(\log^2n)$。

## 24. 我的理解

> [!success]+ 应形成的心智模型
> 双调排序不是让每个线程独立排序一块数据，而是让全部线程共同执行一张固定比较网络。`bf_sz/k` 决定当前处理多大的双调结构，`stage/j` 决定比较距离，XOR 决定比较伙伴，方向位决定升序或降序。同一 stage 的比较对可以并行，stage 之间必须同步。串行版已经包含这张并行网络，CUDA 只是把同一阶段原本逐个执行的比较对交给大量线程同时完成。

## 25. 一页速记

```text
双调排序 = 构造双调序列 + 双调归并

最小操作：compare–exchange
双调序列：先升后降 / 先降后升

k = 2,4,8,...,n          当前蝶式规模
j = k/2,k/4,...,1        当前比较距离
partner = i ^ j          比较伙伴
ascending = ((i & k)==0) 比较方向

并行原则：
同一 stage 的比较对并行
不同 stage 之间同步

复杂度：
总工作量 O(n log²n)
并行深度 O(log²n)

CUDA 限制：
__syncthreads() 只能同步一个 block
跨 block 同步通常依靠多次 kernel launch
```
