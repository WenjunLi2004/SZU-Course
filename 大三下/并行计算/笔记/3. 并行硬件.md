核心脉络其实就是：**串行太慢（冯·诺依曼瓶颈） -> 尝试在单核上压榨性能（缓存、虚拟内存、指令级并行） -> 硬件走向真并行（SIMD、MIMD网络互连） -> 软件如何适配与评估（并行程序设计与Amdahl定律）**
## 1. 为什么需要改进？（冯·诺依曼架构的局限）

**在深入并行之前，必须明白单核架构面临的困境**。
传统的冯·诺依曼体系由内存和CPU（控制单元CU、运算单元ALU、寄存器）组成

- **冯·诺依曼瓶颈**：处理器与内存**物理分离**，数据必须通过**总线**来回搬运，计算速度远超数据传输速度，导致“内存墙”现象，处理器长期等待数据，算力无法充分释放

为了打破这个瓶颈，硬件工程师在**单核层面**做出了诸多改进：

### 1.1 存储层面的改进：缓存与虚拟内存

- **缓存 (Cache) 机制**：利用**局部性原理**（空间局部性、时间局部性）把常用的数据放在离CPU更近的地方
    
    - 为了解决多核心带来的数据一致性，引入了 **写回 (Write Back)** 和 **写直达 (Write Through)** 策略
        
- **==重点：虚拟内存 (Virtual Memory)==**：
    
    - **核心痛点**：如果运行超大程序或数据集，主存（物理内存）根本装不下
        
    - **解决思路**：虚拟内存其实是充当了辅助存储（硬盘）的“缓存” 。它同样利用了时空局部性原理，**只在主存中保存许多==正在运行的程序中的活跃部分==** 。不活跃的部分暂时放在硬盘里，从而**骗过**程序，让它以为自己拥有几乎无限的连续内存空间
        

### 1.2 执行层面的改进：指令级并行 (ILP) 与多发射

尝试让多个处理器组件同时执行指令来提高性能

- **流水线 (Pipelining)**：像工厂流水线一样，把指令拆分为不同阶段（如获取、比较等），让不同的功能单元接力执行，隐藏延迟
    
- **==重点：多发射 (Multiple Issue)==**：
    
    - 流水线同一时刻进入的还是单条指令，而多发射通过**复制功能单元**，尝试在同一时刻**同时启动（发射）多条不同的指令**
        
    - **静态多发射**：由==编译器==在编译阶段提前安排好哪些无依赖的指令可以打包并行发射 
        
    - **动态多发射**：由==处理器硬件==在运行时实时判断并安排并行发射（这类处理器被称为超标量处理器）
        
- **硬件多线程**：当前线程因为等待数据暂停时，CPU快速切换到另一套寄存器运行另一个线程，让核心“假装”多核，不闲着

## 2. 硬件层面的真并行 (Flynn分类法)

当单核改进达到物理极限，真正的多处理器并行成为必然根据指令流和数据流的数量，体系结构被分为 SISD, SIMD, MISD, MIMD

### 2.1 SIMD (单指令流多数据流)

一个控制单元发出一条指令，多个执行单元同时对不同的数据执行这 **==同一种操作==**（数据并行） ，适合极度规律的密集运算

- **==重点：向量处理器 (Vector Processors)==**：
    
    - 传统的CPU操作单个数据（标量），而它直接对**数据的数组或向量进行操作**
        
    - **架构特点**：拥有能存储操作数向量的**向量寄存器**，以及**交叉存储器**（内存分多个库，连续访问基本无延迟） 。支持跨步内存访问 。
        
    - **优缺点**：内存带宽极高，向量化编译器极易优化；但**缺点是难以处理不规则的数据结构，且可扩展性受限**
        
- **图形处理器 (GPU)**：本质也是利用 SIMD 并行理念，拥有数千个弱核心（流处理器 SP），极其擅长重复简单运算，目前广泛用于游戏渲染、AI训练和科学计算 

- 缺点：
	1. **所有数据通路必须执行相同命令或者空闲**：SIMD 最大的痛点，专业术语叫**分支发散**，因为整个系统只有一个控制单元在发射指令
	2. **必须同步运行**：所有的处理单元共享同一个指令流
	3. **没有存储区**：经典 SIMD 架构中，各个数据通路（运算单元）内部没有指令寄存器（PC，程序计数器）和指令缓存，只有存储数据的寄存器，它们完全依赖中央控制单元喂给它们指令
	4. **适合大型数据并行问题**：SIMD 非常死板，极度害怕复杂的控制逻辑（如大量的 if-else、switch 语句）和不规则的数据读取

### 2.2 ==重点：MIMD (多指令流多数据流)==

支持在**多个数据流**上运行**多个不同的并行指令流** 
每个核心完全独立，有自己的控制单元和数据通路，异步运行，没有全局时钟 

MIMD 根据内存组织方式分为两大阵营：

#### A. 共享内存系统 (Shared Memory)
![[Pasted image 20260425132147.png#pic_center|400]]
- **概念**：一组自主处理器通过==**网络**==连接到同一个物理内存系统，每个处理器都能访问所有的内存位置，核心间通过==**读写共享变量**==来进行隐式通信
    
- **UMA架构**：即均匀内存访问，**所有核心访问所有内存位置的时间都是相同的**，目前主流的多核CPU（如Intel, AMD的家用处理器）多采用这种模式
    >相当于一个圆形图书馆，圆上到中心的路程相同
    
    ![[Pasted image 20260425132258.png#pic_center|375]]
- **==新痛点（Cache 一致性）==**：多个核心都有自己的缓存，如果都修改同一个共享变量，会导致数据打架
    - 例子：
	1. **加载**：核心 0 和核心 1 都从内存读取了 `x=2` 到自己的私有 Cache 中
	2. **修改**：核心 0 执行 `x = x + y0`（假设此时核心 0 将其 Cache 中的 `x` 更新为 4）
	3. **隐患**：此时核心 1 的 Cache 里 `x` 依然是旧值 `2`，它并不知道 `x` 已经被改了
	4. **错误结果**：核心 1 执行 `z1 = x + y1` 时，会使用旧值 `2` 进行计算，导致 `z1` 的结果发生逻辑错误
	
	**解决方案：**
    - _监听协议 (Snooping)_：大家都盯着总线，谁改了数据就广播，其他人把自己的副本标记作废
        
    - _目录协议 (Directory)_：用一个类似全局登记册的目录记录状态，更新时查目录并精准通知相关核心作废副本
        

#### B. 分布式内存系统 (Distributed Memory)

- 每个节点都有自己私有的内存，相互之间通过商用网络（如以太网）连接，组成集群
    
- 需要显式的消息传递（类似于网络发包）来进行通信

## 3. 并行系统的底层经络：互连网络

==**网络**==决定了数据的搬运速度，极大地影响了并行系统的性能

- **共享内存网络**：主要用**总线**（分时共享，同一时刻一人发多人收）
    ![[Pasted image 20260425133340.png]]
	或**交换互连**（如交叉开关，允许多对设备同时通信，快但贵）
    ![[Pasted image 20260425133448.png]]
- **分布式内存网络**：分为**直接互连**（节点与相邻节点直接连）
![[Pasted image 20260425133552.png]]
- 和**间接互连**（节点通过专门的交换机/路由器转发）
![[Pasted image 20260425143757.png]]
### 3.1 ==重点网络拓扑：超立方体 (Hypercube)==

- 它是一种高度连接的**直接互连**网络
    
- **归纳式构建** ：
    
    - 一维：2个节点直接相连（线段）
        
    - 二维：两个一维网络连接对应节点（正方形）
        
    - 三维：两个二维网络连接对应节点（立方体）
        
    - 四维：两个三维网络连接对应点
        ![[Pasted image 20260425143740.png]]
- **特性**：若节点数为 $p$，则边数为 $p \log_2 p / 2$ 。这种结构通信延迟极低，因为任意两点间的最多跳数非常小。
    

### 3.2 ==重点评估指标：等分宽度 (Bisection Width)==

- **概念**：将网络节点集拆分为两个相等部分所需删除的**最小链接数**
    
- **为什么重要？** 它是衡量**网络质量和同时通信数量**的指标 。它代表了当网络一半节点试图同时与另一半节点通信时，网络最狭窄的“瓶颈”有多宽（不对链路数量直接计算，而是对链路带宽求和）

## 4. 并行软件：如何驯服硬件

硬件搭好了台子，如果软件还是串行逻辑，性能依然无法提升。

- **SPMD (单程序多数据)**：写一个单一的可执行程序，通过条件分支让不同线程/进程根据自己的ID（rank）去执行不同代码段（最主流的并行编程方式）
    
- **竞争条件与同步**：多个线程同时修改一个全局变量会导致结果的**非确定性**（每次运行结果不一样） 。必须引入**临界区**和**互斥锁 (Mutex)**，保证同一时刻只有一个线程能修改该变量
    

### 4.1 并行程序的性能评估

- **加速比 (Speedup, $S$)**：$S = T_{serial} / T_{parallel}$ （串行耗时 / 并行耗时）
    
- **效率 (Efficiency, $E$)**：$E = S / p$ （其中 $p$ 为核心数）
    
- **阿姆达尔定律 (Amdahl's Law)**：程序中不可并行的串行部分，决定了加速比的上限 。即便核心数无限多，加速效果也会被那小部分的串行代码拖累
    
- **可扩展性 (Scalability)**：
    
    - **强可扩展性**：问题规模不变，增加核心数，效率能保持不变
        
    - **弱可扩展性**：按增加核心数的相同比例增加问题规模，效率能保持不变
        

### 4.2 编写并行程序的范式：Foster 方法论

编写并行程序标准四步走 ：

1. **划分 (Partitioning)**：将计算和数据拆分成极小的任务，暴露最大并行度
    
2. **通信 (Communication)**：确定任务之间需要交换什么数据
    
3. **凝聚 (Agglomeration)**：将小任务和通信合并成较大任务，消除不必要的内部通信
    
4. **映射 (Mapping)**：将合并好的任务分配给具体的进程/线程，目标是**负载均衡**并最小化跨线程通信
