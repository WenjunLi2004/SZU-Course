## 一、为什么还要有 I/O 软件

底层设备差别很大：

- <u>磁盘</u>按块读取
- <u>键盘</u>按字符输入
- <u>打印机</u>只能输出
- 不同厂商控制器的寄存器也不同

用户程序显然不应该了解：

```
某型号控制器的状态寄存器地址
DMA寄存器如何设置
设备完成后产生哪个中断
```

所以 I/O 软件要把复杂的硬件==**封装**==起来，为上层提供统一接口

两个总体目标：
1. 让 CPU 与 I/O 设备并发，**提高资源利用率**
2. 向上提供**简单、统一的抽象接口**

---

# 二、设备独立性

设备独立性是第五章的重要名词

> **应用程序使用==逻辑设备==，不依赖某一台具体物理设备**

例如程序只表达：

```
向打印设备输出这份文档
```

而不是写死：

```
必须使用3号控制器下的HP某型号打印机
```

操作系统再把逻辑设备映射到一台可用的物理设备：

```
逻辑打印机
      ↓ 映射
物理打印机2
```

这样即使：

- 更换设备型号
- 改用另一台同类设备
- 更换驱动程序

应用程序通常也不需要修改

## 设备独立性的作用

### 1. 统一命名

用户使用逻辑名称，不直接使用硬件地址

### 2. 提高可移植性

程序不依赖具体设备型号

### 3. 便于重新分配

原设备故障或繁忙时，可以映射到另一台同类设备

### 4. 隐藏硬件差异

不同设备最终都可表现为类似：

```
open();
read();
write();
close();
```

# 三、I/O 软件的四个层次

 I/O 软件由上到下划分成四层：用户层软件、设备独立性软件、设备驱动程序和中断处理程序

```
用户程序
   ↓
① 用户层 I/O 软件
   ↓
② 设备独立性软件
   ↓
③ 设备驱动程序
   ↓
④ 中断处理程序
   ↓
设备控制器与硬件
```

## 1. 用户层 I/O 软件

离用户最近，负责：

- 提供库函数和系统调用接口
- 格式化输入、输出
- 提交 I/O 请求
- 实现部分 SPOOLing 功能

例如：

```
printf("hello")
read(fd, buf, 4096)
```

`printf()` 属于用户层库函数，继续向下才会进入系统调用和内核 I/O 软件

---

## 2. 设备独立性软件

这是统一管理层，负责与具体设备无关的工作：

- 逻辑设备名到物理设备的映射
- 权限和保护检查
- 缓冲管理
- 设备分配与释放
- 统一不同设备的数据块大小
- 错误报告
- 选择对应设备驱动程序

可以把它理解成“设备管理总台”

---

## 3. 设备驱动程序

设备驱动已经与具体硬件有关

它负责：

- 把通用请求转换为具体设备命令
- 设置控制器寄存器
- 检查设备状态
- 启动 DMA 或设备操作
- 与具体型号的控制器交互

例如上层说：

```
读取第100个逻辑块
```

磁盘驱动需要将其转化为底层控制器认识的命令和参数

> **设备独立性软件负责通用管理，驱动程序负责具体设备**

---

## 4. 中断处理程序

位于最底层软件

设备操作完成后产生中断，中断处理程序负责：

- 保存必要现场
- 读取设备完成状态
- 处理错误
- 标记 I/O 完成
- 唤醒等待该 I/O 的进程
- 恢复执行

因此，一次读磁盘可以理解为：

```
用户发出 read
→ 设备独立层检查、映射、分配
→ 磁盘驱动设置控制器/DMA
→ 磁盘执行
→ 完成后产生中断
→ 中断程序唤醒进程
→ read 返回
```

# 四、设备分配

多个进程可能同时请求同一台设备，操作系统需要判断：

1. 有没有空闲**设备**
2. 连接该设备的**控制器**是否可用
3. 连接控制器的**通道**是否可用

在通道式系统中，一条完整通路是：

```
通道 → 控制器 → I/O设备
```

只找到空闲设备还不够；**若唯一可达的控制器或通道正忙，该设备暂时也无法工作**

---

## 五、设备分配的四张表

**四种核心数据结构**

### 1. 系统设备表 SDT

系统总目录，记录系统中所有设备，例如：

- 设备类型
- 设备标识
- 指向 DCT 的指针
- 驱动程序入口

可以把它理解为：

> **先从 SDT 找到系统中符合要求的设备**

### 2. 设备控制表 DCT

每台设备通常对应一张 DCT，记录：

- 设备类型与标识
- 忙或闲
- 是否已有进程等待
- 指向其控制器的指针
- 等待该设备的进程队列

### 3. 控制器控制表 COCT

记录：

- 控制器是否空闲
- 它连接到哪个通道
- 等待控制器的队列

### 4. 通道控制表 CHCT

记录：

- 通道是否空闲
- 它连接哪些控制器
- 等待通道的队列

记忆顺序：

```
SDT：全系统设备目录
DCT：某台设备
COCT：某个控制器
CHCT：某个通道
```

---

## 六、一次设备分配过程

进程请求**某类**设备后，可以抽象成：

```
1. 查 SDT，找到合适设备
2. 查 DCT，设备是否空闲
3. 查 COCT，控制器是否空闲
4. 查 CHCT，通道是否空闲
5. 全部可用，建立完整通路并启动 I/O
```

如果某一层不可用，进程通常进入相应等待队列：

```
设备忙     → 等设备
控制器忙   → 等控制器
通道忙     → 等通道
```

因此设备分配不只是“把打印机给进程”，而是分配一条可工作的 I/O 通路

# 七、SPOOLing 技术

SPOOLing 是这一部分最重要的考点

全称：

> **Simultaneous Peripheral Operations On-Line**  
> 外围设备联机并行操作

它使用磁盘模拟过去的脱机输入、输出系统，它需要：

- 多道程序系统
- 高速随机存取外存，通常是磁盘

---

## 八、先看打印机问题

打印机是独占设备假设三个进程都想打印：

```
P1：打印100页
P2：打印2页
P3：打印5页
```

没有 SPOOLing 时，如果 P1 独占打印机，P2、P3 必须长期等待

有 SPOOLing 后，各进程不是直接占用打印机，而是快速把输出写入磁盘中的**输出==井==**：

```
P1 ─┐
P2 ─┼→ 输出井（磁盘队列） → 输出进程 → 物理打印机
P3 ─┘
```

用户进程把内容写入磁盘后，就可以继续执行专门的输出进程再按顺序慢慢控制打印机

---

# 九、SPOOLing 系统的组成

## 输入方向

```
输入设备
→ 输入缓冲区
→ 输入进程 SPi
→ 磁盘输入井
→ 用户作业读取
```

## 输出方向

```
用户进程→ 磁盘输出井→ 输出进程 SPo→ 用户进程
→ 磁盘输出井
→ 输出进程 SPo
→ 输出缓冲区
→ 输出设备→ 输出设备
```

其中：

- **井**位于磁盘
- **缓冲区**位于内存
- 输入、输出进程负责在设备、缓冲区和井之间搬运数据

---

# 十、SPOOLing 的三个作用

## 1. 提高 I/O 速度

这里不是让物理打印机真的打印得更快，而是：

> 用户进程只需快速写入磁盘，不必同步等待慢速打印机

所以提高的是系统观察到的 I/O 提交效率和 CPU、设备并行程度

## 2. 将独占设备改造成共享设备

多个进程都可以同时提交打印任务，物理打印机最终仍是一份一份打印

因此这里的“共享”是：

```
逻辑上共享，物理上仍然串行使用
```

## 3. 实现虚拟设备

操作系统为每个进程在输出井中分配区域并建立 I/O 请求表

每个进程都感觉：

```
我拥有一台自己的打印机
```

实际上它们拥有的是多个**逻辑打印机**，底层只有一台物理打印机

---

# 十一、SPOOLing 与普通缓冲的区别

|对比项|缓冲|SPOOLing|
|---|---|---|
|主要位置|内存|井主要位于磁盘|
|容量|较小|较大|
|目的|缓和速度差|排队、并行、虚拟设备|
|能否把独占设备逻辑共享|通常不能|可以|
|典型例子|单缓冲、双缓冲|打印任务队列|

一句话：

> **缓冲是临时中转，SPOOLing 是利用磁盘建立大型 I/O 排队系统**
