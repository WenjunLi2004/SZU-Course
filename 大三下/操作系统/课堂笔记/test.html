1. 操作系统引论

预习

操作系统的目标

疑问：难道计算机可以没有操作系统吗？

  • 其实是可以的，人工操作硬件：用户独占全机，CPU等待人工操作。
  • 方便性：没有OS，你想打开一个文档文件，需要自己写驱动去读硬盘、解析文件格式、驱动显卡显示像素。OS提供了图形界面、文件管理、命令解释器等，让普通人也能轻松使用计算机。
  • 有效性：没有OS，内存如何分配给多个程序？CPU如何在多个任务间切换？外设谁先用谁后用？OS作为“大管家”，统一管理和调度所有硬件资源（CPU、内存、硬盘、网络等），让它们高效、合理地协同工作，避免冲突和浪费。
  • 可扩充性：没有OS，每增加一个新硬件（比如新型号的显卡），所有软件都可能需要重写来适配它。OS提供了标准的驱动接口，硬件厂商只需提供针对OS的驱动，所有应用软件就都能使用它。
  • 开放性：没有OS，每个软件开发商都要为一台计算机单独开发，没有通用标准。OS定义了应用程序和计算机交互的标准接口（API），使得软件可以在遵循同一标准的任何计算机上运行，实现了软硬件的解耦和生态繁荣。

OS 发展

  1. 从人工操作硬件发展到脱机输入/输出(Off-Line I/O)方式。增加一个额外的硬件脱离主机来处理输入和输出，从而减少了CPU的空闲时间和提高I/O效率。
  2. 进一步发展到早期的批处理操作系统：单通道 -> 多通道，分为 Input - Execute - Output。
    资源利用率高，吞吐量大。
    面临的问题：并发和资源共享引发的管理难题
    • 处理机管理问题（谁该用CPU？用多久？）
    • 内存管理问题（程序放哪？互不干扰？）
    • I/O设备管理问题（谁先用打印机？）
    • 文件管理问题（数据如何组织、保护？）
    • 作业管理问题（如何组织作业流？）

所以操作系统的定义： 一组 控制和管理计算机硬件和软件资源，合理对各类作业进行调度，方便用户使用的 程序的集合。

它不是一个单一的程序，而是由许多模块化、各司其职的程序共同构成的，例如：

  • 内核：最核心的部分，负责管理CPU、内存、进程等关键资源。它通常不是一个可以直接运行的“应用”，而是为其他程序提供服务的底层基础。
  • 系统程序：例如用于文件操作的命令（cp, mv）、用于进程查看的命令（ps）、Shell（命令解释器）等。
  • 驱动程序：用于和特定硬件（如显卡、声卡）通信的特殊程序。
  • 用户接口程序：如图形界面（GUI）的窗口管理器、桌面环境等。

两条发展路径

  1. 解决效率问题
    • 多道批处理系统：实现了自动调度和资源管理，但缺乏交互性(用户提交作业后只能等待)。
    • 分时系统：引入了 “时间片” 概念。CPU时间切成极小的片段，轮流分配给多个联机用户。由于切换速度极快，每个用户都感觉自己在独占主机。
    • 实时系统：在分时系统“及时”的基础上，对“时间”的要求达到了严格、可预测的级别。
  2. 普及到个人
    • 单用户单任务（如MS-DOS）：这是操作系统理念的“简化版”或“回溯”。由于早期微机性能极弱，它只实现了最基础的文件管理和设备驱动，没有分时多任务能力。用户一次只能运行一个程序，命令行操作。
    • 单用户多任务（如Windows系列、经典Mac OS）：分时系统思想在个人电脑上的实现。
    • 多用户多任务（如Unix、Linux及衍生的macOS）：完整的分时系统在服务器和高端工作站上的体现。多个用户能够同时、独立地使用同一台计算机：每个用户拥有自己的账户、文件、设置和运行环境，操作系统负责安全地隔离和管理这些资源，确保彼此互不干扰—— 并发。

操作系统四大基本特性

  1. 并发 Concurrence：多核并行，单核并发——宏观上多个程序在同时运行，微观上分时交替执行。
  2. 共享 Sharing：系统资源（内存、CPU、设备等）供内存中多个并发执行的程序共同使用。
  3. 虚拟 Virtual：通过技术将物理实体变为逻辑上的对应物（如虚拟内存），方便用户使用。
  4. 异步性 Asynchronism：进程以不可预知的速度向前推进，允许程序在运行中被中断。

2. 进程管理

进程是操作系统最核心的概念。

0. 为什么要引入进程

要理解进程，首先要理解程序是如何运行的。

（1）顺序执行

早期，程序是严格按顺序一步步执行的，前一操作完成才能执行后继操作。

三个特征：

  1. 顺序性：下一操作要等待前一操作结束
  2. 封闭性：执行时独占资源，不受外界影响
  3. 可再现性：只要重复执行，就会获得相同结果

程序：Input -- Compute -- Print
每条语句也可以看做一个程序。

（2）前趋图：描述执行的先后关系

有向无环图：箭头“→”表示偏序或前趋关系。

  • Pi → Pj，称Pi是Pj的直接前趋，而称Pj是Pi的直接后继。

（3）并发执行

现代操作系统为了提高效率，会让多个程序同时运行，导致程序：

  1. 间断性：在并发环境下，多个程序共享系统的资源，所以当另一个程序占用需要的资源时，必须暂停等待，等待空闲再执行。
  2. 失去封闭性。
  3. 不可再现性：即使是同样的程序、同样的输入，每次运行的结果都可能不一样。

——使得纯粹的 “程序”在并发环境下无法正确运行。

为了保证程序能在多程序环境下安全、正确地并发执行，操作系统必须引入 进程 这个概念，给每个运行的实例分配一个独立的进程控制块（PCB）来记录它的现场和状态。

1. 进程的基本概念

1. 什么是进程？(核心定义与结构)

  • 官方定义：进程是程序的一次执行，是系统进行资源分配和调度的一个独立单位。
  • 进程的结构由三部分组成：
    1. 程序：代码段，描述进程要完成的功能。
    2. 数据：数据段，进程执行时所需要的数据区。
    3. 进程控制块 PCB：最重要的部分！PCB 是一种数据结构，用于标识进程的存在，并记录进程执行过程各个时刻的状态特征。哪怕两个进程共享同一段代码程序，它们也必须拥有各自独立的 PCB 和数据集合。

所以进程有四个特性：

  1. 动态性：创建——执行——消亡
  2. 并发性：多个进程共存于内存中，并同时执行
  3. 独立性：资源独立，互不干扰
  4. 异步性：速度不可预测

简单理解 进程 & 并发

核心在于 PCB + 独立数据区 → 完美重启

  • PCB存储能够重启的状态特征：PC，寄存器状态...
  • 数据独立：不被污染

所以说 并发是宏观上同时，微观上交替。

进程 vs. 程序 (经典对比)

  • 进程是动态的执行实体，而程序是静态的数据与指令的集合。
  • 进程有生命周期（会创建、消亡），而程序是永存的（只要不删就一直存在硬盘里）。
  • 进程执行需要竞争 CPU 等资源，程序存储只需要存储器。
  • 一个程序运行时可以衍生出多个进程。

2. 进程分类

  1. 系统进程 （VIP 玩家）：运行在管态（核心态、系统态）。它们被分配了初始资源，可以直接独占使用，并且拥有最高优先权，可以为所欲为，比如执行一切指令、直接做 I/O 操作、访问受保护的寄存器。
  2. 用户进程（普通玩家）：运行在目态（用户态）。它们没有特权，必须通过“服务请求”的方式来竞争资源。不能直接操作 I/O 设备，只能执行指定的指令和访问指定的内存。

3. 进程的“生命周期”：三大基本状态

  • 创建状态 Created：进程刚刚开始初始化，已经分配了 PCB，但还没有获得所需的物理资源（比如程序数据还没读入内存），也没有进入调度队列。
  • 就绪状态 Ready：万事俱备，只欠东风。进程已经获得了除 CPU 以外的所有资源，正乖乖待在就绪队列里排队等候分配 CPU。
  • 执行状态 Running：成功获得 CPU，正在执行指令。
  • 阻塞状态 Blocked：进程在运行中遇到了需要等待的事件（比如请求 I/O 读取文件、请求缓冲空间等），导致暂时无法继续，于是 主动放弃 CPU 处于暂停状态，进入阻塞队列。
  • 终止状态 Terminated：进程执行完毕或被外力异常终止。此时系统正在回收它的全部资源，它永远不能再获得 CPU 执行。
New → Ready → Running → Terminated
                ↓
             Blocked
                ↓
              Ready

4. 进阶大 Boss：挂起状态 (Suspend) 与 七状态转换

挂起状态 是一种 更深度的静止状态，被挂起的进程不能马上投入运行。

  • 为什么挂起？ 常见原因：终端用户想要暂停程序进行调试、父进程请求同步、操作系统的负荷太重需要减轻内存压力，或者是操作系统需要检查资源使用情况。
  • 四个派生状态与转换原语：因为有了挂起 (suspend) 和激活 (active) 这两个操作，原本的就绪和阻塞裂变成了四个状态：
    • 活动就绪 (Readya) 被挂起 → 静止就绪 (Readys)
    • 活动阻塞 (Blockeda) 被挂起 → 静止阻塞 (Blockeds)
    • 反之，使用“激活”原语可以从静止状态恢复到活动状态。

5. PCB(Process Control Block) 进程控制块

PCB是进程存在的唯一标志，OS是根据PCB来对并发执行的进程进行控制和管理的。

1. PCB 里到底装了什么？

可以把 PCB 想象成进程的 “个人档案”和“工作日志”，里面记载了四个核心信息：

  • 进程标识符 PID：进程的身份证号，用来唯一标示这个进程。
  • 处理机状态：核心！ 里面保存了 CPU 内部各种寄存器的内容。当进程被暂停时，当前的计算进度就会“截图”保存在这里，等下次恢复运行拿出来接着算。
  • 进程调度信息：记录了进程的优先级、等待了多久等，帮助操作系统决定下一个让谁上 CPU 运行。
  • 进程控制信息：记录了这个进程拥有哪些资源（比如分配了哪些内存、打开了哪些文件）。

2. 操作系统怎么收纳这堆 PCB？

两种主流的组织方式：

  1. 链接方式：操作系统把具有相同状态的 PCB 用指针链接成一个队列。比如所有的就绪状态 PCB 串成一个“就绪队列”，阻塞状态的串成“阻塞队列”。
  2. 索引方式：像查字典的目录，系统建立几张“索引表”（比如就绪索引表、阻塞索引表），表里记录着指向各个 PCB 的地址。要找哪个状态的进程，直接查表就行。

2. 进程控制

进程控制，就是操作系统对“进程一生”的管理：创建、运行、等人、被叫醒、暂停、恢复、死亡。

本质：操作系统不断移动进程的 PCB，让它在不同队列和状态之间变化。

2.1 重点：父进程和子进程的关系

  • 父进程：系统或用户首先创建的进程。
  • 子进程：父进程创建的进程。
  1. 子进程由父进程创建或撤销：父进程有权管理子进程，但子进程不能反过来控制父进程。
  2. 子进程可以继承父进程资源：比如父进程打开了某些文件，子进程可能继承文件句柄；父进程有某些权限，子进程可能部分继承。
  3. 父子进程可以同时运行，也可以有先后关系：比如父进程创建子进程后，可以继续干自己的；也可以等子进程结束后再继续。
  4. 这种关系记录在 PCB 里：PCB 不只是记录“我是谁”，还记录“父进程是谁，孙子进程是谁”。

2.2 原语

原语 = 操作系统中不可分割的基本操作（要么成功，要么完全不发生）。

比如“把进程从执行态改成阻塞态”时，至少要做几件事：

  1. 保存 CPU 状态
  2. 修改 PCB 状态
  3. 插入阻塞队列
  4. 重新调度 CPU

这些事情必须作为一个整体完成。不能只改了状态，还没插入队列；也不能插入队列了，但 CPU 状态没保存。

原语 = 操作系统内核中不可中断的动作  
特点 = 要么全做，要么全不做  
作用 = 保证进程状态转换不会乱

2.3 进程创建 create

什么时候会创建进程？用户登录、系统调度作业、程序请求服务、主动创建。Linux 里常见的是 fork()。

底层做了些什么？

  1. 申请空白PCB：PCB 是进程存在的标志
  2. 分配资源：分配内存、文件、I/O 资源等
  3. 初始化PCB：进程标识符 PID、父进程是谁、当前状态、程序入口地址、CPU 寄存器初始状态、资源信息、优先级
  4. 插入就绪队列：排队等 CPU 调度

2.4 进程终止 exit / terminate

主要三类：正常结束（如 return 0;）、异常结束（如数组越界、除零错误）、外界干预（如任务管理器结束任务）。

终止过程像“退学手续”：

  1. 找到它的 PCB
  2. 查看它当前状态
  3. 如果正在执行，立刻停掉
  4. 终止它的子孙进程
  5. 回收资源
  6. 把 PCB 从队列中移出
进程死了，不只是“程序不跑了”，还要释放它占用的一切资源（否则会出现资源泄漏）。

2.5 进程阻塞 block ：进程主动说“我先等一下”

阻塞不是进程坏了，而是它暂时等条件（如等待慢速 I/O 操作完成）。

引起阻塞的事件：请求系统服务、启动某种 I/O 操作、等待新数据到达、暂时无工作可做。

阻塞是进程自身的主动行为。

阻塞底层在做什么？

  1. 保存现场信息：能继续在停下的位置往下执行
  2. 状态从执行态改为阻塞态
  3. 把 PCB 插入阻塞队列
  4. 重新调度CPU
  5. CPU切换给另一个就绪进程

2.7 进程唤醒 wakeup：条件到了，把它从等待区叫回来

阻塞之后，进程不是自己回来，而是要被唤醒。此时相关进程或OS调用 wakeup 原语。

唤醒过程：

  1. 从阻塞队列中移出 PCB
  2. 把状态从阻塞改为就绪
  3. 插入就绪队列
  4. 等待 CPU 调度

注意：唤醒之后不是马上执行，而是进入就绪队列。

2.8 挂起 suspend：把进程从内存“搬到外存”

阻塞：进程在等事件；挂起：进程被暂时移出内存。

  • 活动 = 在内存中
  • 静止 = 被换出到外存

本质：挂起 = 为了节省内存，把进程暂时换出。

2.9 激活 active：把挂起的进程重新搬回内存

激活就是挂起的反向过程。激活不是一定立刻运行，而是回到“活动状态”。

总结

操作原语状态变化核心动作
创建create无 → 就绪申请 PCB、分配资源、初始化、入就绪队列
终止terminate / exit任意 → 终止停止执行、终止子孙、回收资源、移出 PCB
阻塞block执行 → 阻塞保存现场、入阻塞队列、重新调度
唤醒wakeup阻塞 → 就绪出阻塞队列、改为就绪、入就绪队列
挂起suspend活动 → 静止换出到外存、释放内存
激活active静止 → 活动调入内存、恢复为活动状态

3. 进程同步

进程同步，就是让多个并发进程在共享资源、互相合作时，不乱、不抢、不出错，并且结果可重复。

3.1 为什么需要进程同步？

多个进程并发执行，面临资源共享的麻烦。如果都在操作同一个东西，就可能出错。不是算法错了，而是执行顺序乱了。

3.2 进程同步到底在同步什么？

✅ 同步 = 让多个进程按照某种正确的配合关系运行。包含两类关系：

  1. 间接相互制约关系（申请同一资源）
  2. 直接相互制约关系（有明确的合作顺序，如输入与运算）

3.3 临界资源

临界资源：一次仅允许一个进程访问的共享资源（如打印机、共享变量）。共享 + 修改 + 同时访问会出错 ≈ 临界资源。

3.4 生产者-消费者问题

两个问题：1. 顺序同步（缓冲池空/满时要等），2. 互斥访问（不能同时修改缓冲池）。

3.6 为什么乱序交叉共享变量 counter 会出错？

counter = counter + 1 在机器内部通常会拆成多条指令（读寄存器 -> 加 1 -> 写回）。乱序交叉执行会导致结果错误。这种问题叫做：竞争条件。

3.7 临界区 critical section

临界区：进程中访问临界资源的那段代码。（只读不写不算临界区）

repeat
    entry section;     // 进入区
    critical section;  // 临界区
    exit section;      // 退出区
    remainder section; // 剩余区
until false;

3.8 同步机制必须遵循的四条规则

  1. 空闲让进
  2. 忙则等待（互斥）
  3. 有限等待
  4. 让权等待（阻塞释放 CPU，避免忙等）

3.9 信号量机制：（重点）

信号量本质：一个带规则的资源计数器。只能通过两个原子操作访问：wait(S) (P 操作) 和 signal(S) (V 操作)。

记录型信号量：真正体现 block / wakeup

记录型信号量包含了 可用资源数量(S.value) + 等待队列(S.L)。

wait(S):
    S.value = S.value - 1;
    if S.value < 0 then block(S.L);
先申请资源，S.value < 0 表示阻塞进程的个数。
signal(S):
    S.value = S.value + 1;
    if S.value <= 0 then wakeup(S.L);

3.11 AND型信号量

为了避免死锁，将进程整个运行过程中需要的所有资源，一次性全部分配给进程。

4. 经典线程同步

4.1 进程同步问题的三类矛盾

  1. 互斥：同一个资源，同一时刻只能一个进程访问。
  2. 同步：动作有先后顺序。
  3. 死锁避免。

4.2 信号量应用

关键口诀：先私后公。先执行对资源信号量的 wait，再执行对互斥信号量的 wait。

4.6 哲学家进餐问题

如何避免死锁：

  1. 最多允许 4 个哲学家同时拿筷子
  2. 左右筷子都可用时才允许拿（AND信号量）
  3. 奇偶哲学家拿筷子顺序不同（打破循环等待条件）

4.7 读写锁

引入 readcount 记录读者数量，通过 rmutex 保护该变量：第一个读者负责关门，最后一个读者负责开门。

5. 进程通信

高级通信方式：

  1. 共享存储器 (Share Memory)：速度快，需自己处理互斥/同步。
  2. 消息传递 (Message Passing)：应用最广泛，通过 send / receive 格式化消息。
  3. 管道通信 (Pipe)：连接读写进程的共享文件。

间接通信：通过信箱（mailbox）转发（发送者 → 信箱 → 接收者）。
