## 1. 为什么要引入分页？

连续分配的问题是：

> **内存空闲总量可能够，但作业必须占用一整块连续==物理==内存空间**

那么分页的核心思想是：

> **取消“作业必须连续存放”这个限制**

也就是：不再要求一个作业连续存放，而是把作业拆成若干个固定大小的**页**，分散放入内存中的**物理块**


==**这就是分页最重要的动机**==

## **2. Page ↔ Frame**

分页管理里最重要的一组概念：

| 概念                 | 所属空间       | 含义            |
| ------------------ | ---------- | ------------- |
| **Page**，页         | **逻辑**地址空间 | **程序**被切出来的小块 |
| **Frame**，页框 / 物理块 | **物理**内存空间 | **内存**被切出来的小块 |
| **Page Table，页表**  | OS 维护的数据结构 | 记录每一页放在哪个物理块  |

==**页是操作系统分配内存的最小单位**==

可以这样理解：

> Page 是程序视角的块，Frame 是内存视角的块，页表负责把 Page 翻译成 Frame

例如：

|页号 Page|物理块号 Frame|
|---|---|
|0|17|
|1|8|
|2|25|
|3|19|

意思是：

- 第 0 页放在第 17 块
- 第 1 页放在第 8 块
- 第 2 页放在第 25 块
- 第 3 页放在第 19 块

所以：

> **页号在逻辑地址中是连续的**，但对应的物理块号可以是离散的

---

## **3. 为什么页大小必须等于物理块大小？**

这是分页能简单工作的关键

如果：

> Page 大小 = Frame 大小

那么一个 Page 可以刚好放进一个 Frame

于是地址转换时只需要做一件事：

> **把页号换成物理块号，页内地址保持不变**

==**逻辑地址 A：页号 P ｜ 页内地址 d**==

> 到这里我才悟了，其实是这个经典做法，把逻辑地址拆分表达，这也就对应了为什么是进行除法操作得到页号
> 更印证了为什么 Page 大小 必须等于 Block 大小
> 页内地址 d 的位数也正如Cache里的Block位数一样，表达为Page大小需要的位数

查页表后变成 ==**物理地址：块号 b｜ 块内地址 d**==

**注意：这里的 `d` 不变**

| 计算对象   | 公式             |
| ------ | -------------- |
| 页号 P   | `P = A / L 取整` |
| 页内地址 d | `d = A % L`    |

> 存储中 1KB = 1024B
### **如果 Page 和 Frame 大小不一样会怎样？**

如果 Page 比 Frame 大：

> 一个页放不进一个物理块，需要拆成多个物理块，页表映射会变复杂

如果 Page 比 Frame 小：

> 一个物理块里可能放多个页，OS 还要管理块内的小空间，碎片和定位都会变复杂

这样就失去了分页最优雅的设计：

> 一个页正好对应一个物理块，页内偏移可以直接变成块内偏移

**任何一个页都可以装入任意一个物理块**

## 4. 例题：逻辑地址转换物理地址

题目：分页式存储管理，**页面大小为 2KB** 进程 A 的页表如下，求**逻辑地址 4832** 的物理地址

|页号|块号|
|---|---|
|0|17|
|1|8|
|2|25|
|3|19|

1. 页面大小：2KB = 2048B ，逻辑地址 4832
2. 求页号和页内地址：4832 / 2048 = 2 余 736
	1. `P = 2`
	2. `d = 736`
3. 查页表：`P = 2` -> `b = 25`
4. 计算物理地址：`25 × 2048 + 736 = 51936`

## 5. 分页解决了什么，又带来了什么？

分页解决的是连续分配中的**外部碎片**问题

> 因为作业不再要求占用一整块连续空间，只要能找到**若干个空闲物理块**即可

带来了新的问题：分页会产生**页内碎片**

例如页面大小为 4KB，进程大小为 10KB：

|页号|使用情况|
|---|---|
|第 0 页|4KB，装满|
|第 1 页|4KB，装满|
|第 2 页|只用 2KB，剩下 2KB 浪费|

这个浪费发生在最后一页内部，所以叫页内碎片，也可以理解为一种内部碎片

为什么页内碎片不能给其他进程用？

 **再次回顾：==页 / 物理块是分页系统中分配和映射内存的最小单位==，不能把一个物理块再切开给多个进程共享使用**

## 6. 分页和连续分配的对比

|对比点|连续分配|分页管理|
|---|---|---|
|作业是否必须连续|必须连续|不必连续|
|分配单位|整个作业 / 分区|页和物理块|
|主要问题|外部碎片|页内碎片|
|地址转换|基址 + 偏移|页号查页表得到块号|
|核心数据结构|空闲分区表 / 空闲分区链|页表|

一句话：

> 连续分配是在找一整块连续空间；分页管理是在找若干个离散物理块

## 7. 快表 TLB

分页地址转换有一个性能问题：

> 为了访问一次数据，需要先访问页表，再访问真正的数据

**两次==主存==访问：**
1. 访问==**页表**==，找到物理块号
2. 访问物理地址，读取数据

所以引入快表 TLB

快表可以理解为：

> **页表的高速缓存**，保存最近使用过的一部分页表项

地址转换时：

1. **先查快表**
2. **命中**：直接得到块号 —— **一次快表 + 一次内存**
3. **未命中**：再查内存中的页表，并把结果放入快表 
	—— **一次快表 + 两次内存**

### 例题：计算快表的访问时间
- **快表访问时间为20ns，内存访问为100ns**
1. 若快表查找成功，包括读数据总时间为**120ns**
2. 若快表查找失败，得到总时间为**220ns**

## 8. 单级页表的问题

单级页表的问题是：

> 逻辑地址空间越大，页数越多，页表就越大

比如 ==**32 位地址空间**==，页面大小 4KB：

| 项      | 值                        |
| ------ | ------------------------ |
| 逻辑地址空间 | 4GB                      |
| Page大小 | 4KB                      |
| 页数     | **4GB / 4KB = ==1M 页==** |
| 每个页表项  | 4B                       |
| 页表大小   | **1M × 4B = 4MB**        |

问题在于：

> 页表本身也要占内存，而且单级页表通常需要连续存放

于是引出：

> 多级页表

---

## 9. 两级页表的核心思想

两级页表不是改变分页思想，而是：

> **对页表本身再分页**

它的核心目的：**继续解决页号的连续存放**

> 不必让整个大页表连续放在内存中，也不必一次性装入所有页表项

普通分页是：**程序分页**

两级页表是：**页表也分页**

原来 A：`页号 ｜ 直接查页表`

现在 A：`外层页号 ｜ 内层页号 ｜ 页内地址`

转换过程则增加一层映射：

1. 用外层页号查外层页表：找到某个内层页表的**位置**
2. 用内层页号查内层页表：得到物理块号

## 页表例题
### 题型1：计算各种位数和大小

1. 逻辑地址最少位数
2. 页位数 / 页长度
3. **页大小 / 页内偏移**
4. 页数量 / 一个进程最多有多少页
5. 物理地址最少位数
6. 内存空间大小
---

**1. 一个**32位地址**的计算机系统使用** 二级页表,虚地址被分为**9位顶级页表**,**11位二级页表和偏移**.请问

1. 页面长度
   > 页 / 页面 = page
   >   页表 = page table
2. 空间有多少页面

**Page 长度 = 32 - 9 -11 = 12 位**
- Page ==**大小**== = $2^{12}B$ = **4KB** 

页面==**数量**== = 前面的地址大小 = $2^{20}$

---

**2. 设**==**一页式**==管理系统，向用户提供的逻辑地址空间最大为**16页**，每页2048字节，内存中共有8个存储块。试问逻辑地址至少应为多少位？内存空间有多大？

16页对应页的最大数量 -> **至少4位**
2048对应页的大小 -> **11位**
➡️ 逻辑地址至少15位

8个存储块对应存储数量
➡️ 内存空间 = 存储块大小✖️数量 = 8✖️2KB = 16KB

==**误区：逻辑地址 不等于 物理地址**==
- 逻辑地址只和页数和页大小有关
- 物理地址和内存空间大小有关

### **2. 多级页表概念理解**

新概念：页表项 page table entry, PTE，表示**页表里一行**
- 页表项里存：物理块号 + 标志位

**➡️ 一个==页表页==里能放多少个页表项** = 物理块大小 / 页表项大小
- 虽然页大小 = 物理块大小
- 但是这里不是解释为页大小，而是物理块

e.g. 32 位系统，4KB 页，页表项 4B
- 页内地址 12位，页数 $2^{20}$

> 上面都是**逻辑地址**的角度，下面进入页表
> **页表是放在内存里的数据结构**
> ==**页表本质是数组**==

- 4KB / 4B = $2^{10}$ 个页表项
> 表示一个 4KB 的**内存块**，可以存 1024 条 PTE

页表如果太大，可以被切成很多个 4KB 的小块存放
每个小块能放 1024 行

这个小块才叫：==**页表页**== = 用来存页表内容的一页内存

**为什么页表页也是 4KB？**
- 因为它最终也要放进物理内存的某个 frame 里

**形象理解：**
```
一级页表：
第0项 → 指向一个二级页表页
第1项 → 指向一个二级页表页
第2项 → 指向一个二级页表页
...

二级页表页：
第0项 → 某个物理块
第1项 → 某个物理块
第2项 → 某个物理块
...
```

假设**页面的大小为4KB**,**一个页表项用4B**.若要求用页表来管理地址结构为**36位的虚拟地址空间**，并且==**每个页表只占用一页**==。那么，采用多级页表结构时，需要几级才能达到管理的要求？

页内12位

重点在于一个页表只占用一页：**限制每张页表最多占用4KB内存**

1. 一个页表有**1024**个表项，管理**4MB**大小的虚存空间
	一级页表不能管理64GB的虚拟空间
2. 二级页表有1K个一级页表，管理1K✖️1K个页面,存储量是**4GB**
3. 三级页面能管理4TB的虚拟空间

**重点就是计算逻辑地址空间**

## 课堂练习

有一**基本分页存储管理系统**，假定**页面大小为1024字节**，==**页表采用离散方式放在内存中**==。**每个页表项占用4个字节**。在忽略页表及系统区等占用空间的条件下：（所有数据都是十进制）
❑ **若采用一级页表**，系统能支持的逻辑空间最多为多少？
❑ **若采用二级页表**，系统能支持的逻辑空间最多为多少？
❑ 在二级页表中，现有逻辑地址为542783，求该地址对应的外层页号，外层页内地址和页内地址？

---

**错误：默认逻辑地址等于32位了，实际上大错特错**

1. ==**页表采用离散方式放在内存中**==：页表本身**按页存放**，**每张页表最多占一页**
   >所以才能得到 **一张页表最多管理 256 页**

2. **一级页表只有一张页表**
   >逻辑空间 = 256 × 1024B  = 256KB

3. **二级页表只有两张页表**
   >逻辑空间 = 256 × 256 × 1024B  = 64MB

4. 逻辑地址：542783
	**外层页号 P1 | 外层页内地址 P2 | 页内地址 d**
	>**这就是从除法出发的好处，比分析地址长度更快**
	>页号 P = 542783 / 1024 取整 = 530
	>页内地址 d = 542783 % 1024 = 63
		**对页号继续进行拆分**
		外层页号 P1 = 530 / 256 取整 = 2  
		外层页内地址 P2 = 530 % 256 = 18

> 如果是十进制，直接除法
> 如果是其他进制的话，可以分析地址长度
