真正需要掌握的就三件事：

1. **磁盘结构与寻址**
2. **磁盘访问时间计算**
3. **四种磁盘调度算法**

其中最容易出大题的是第 3 项

## 一、磁盘结构：只记清这四层

```
磁盘
→ 盘片
→ 盘面
→ 磁道
→ 扇区
```

- **盘面**：盘片的正面或反面
- **磁道**：盘面上的同心圆
- **扇区**：把一条磁道切成若干小段，是磁盘读写的基本物理单位
- **柱面**：所有盘面上半径相同的磁道集合

**磁盘传统寻址方式**是：

```
磁头号 Head + 柱面号 Cylinder + 扇区号 Sector
```

### 柱面为什么重要

多个盘面的磁头装在同一个磁臂上，会一起移动

磁头从 20 号磁道移到 50 号磁道后，所有盘面的磁头都位于 50 号磁道，因此这一整组磁道叫作一个**柱面**

> 考试通常不深究扇区内部格式，知道扇区含数据、标识和校验信息即可

# 二、磁盘访问时间

读一块磁盘数据，不是磁头一到就马上完成，而是经历三步：

```
先移动到正确磁道
→ 等目标扇区转到磁头下面
→ 真正传输数据
```

因此：$Ta=Ts+Tr+Tt$

- Ts​：寻道时间
- Tr​：旋转延迟
- Tt​：数据传输时间

---

## 1. 寻道时间 Ts

磁臂移动到目标磁道所花的时间：

$Ts=m×n+s$

- n：移动的磁道数
- m：每移动一条磁道的时间
- s：启动磁臂的固定时间

例如：

```
当前磁道 = 40
目标磁道 = 70
m = 0.1 ms/磁道
s = 2 ms
```

移动距离： n=∣70−40∣=30

**寻道时间**：Ts=0.1×30+2=5 ms

磁盘调度算法主要优化的就是这部分，因为机械移动通常最慢

---

## 2. 旋转延迟 Tr

磁头已到正确磁道，但目标扇区未必刚好在磁头下面，必须等待盘片旋转

若转速为 R RPM：

$$一圈时间=\frac{60}{R}$$

==**平均只需等待半圈**==：

$$平均旋转延迟= \frac{30} {R} s$$

换成毫秒：$Tr​=\frac{30000} {R}​ ms​$

**例如 6000 RPM：Tr​=30000/6000​=5 ms**

### 易错点

- 问**最大旋转延迟**：一整圈
- 问**平均旋转延迟**：半圈
- RPM 是每分钟转数，注意换算为秒

---

## 3. 传输时间 Tt

若：

- b：本次传输字节数；
- N：每条磁道上的字节数；
- r：每秒转数；

则一秒转过 r 条磁道的数据量：$rN$

因此：
$$Tt​=\frac{b} {rN}$$

单位通常是秒

按比例理解：

> 读取半条磁道，就需要半圈时间；读取四分之一磁道，就需要四分之一圈时间

---

## 访问时间题的统一步骤

遇到计算题，固定按下面做：

```
① 求磁道移动距离
② 求寻道时间 Ts
③ 由转速求平均旋转延迟 Tr
④ 由数据量比例求传输时间 Tt
⑤ 三者相加
```

---

# 三、磁盘调度：为什么主要看磁道号

一批进程同时请求磁盘，访问的磁道可能是：

```
55、180、20、90、150……
```

如果磁头无规律来回移动，寻道时间会非常大

因此磁盘调度算法的目标是：==**平均寻道时间少**==

> **重新安排请求顺序，尽量减少磁头总移动距离和平均寻道距离**

计算公式：
$$
总寻道距离=∑∣下一磁道−当前磁道∣
$$
$$
平均寻道距离= \frac {总寻道距离} {请求数}
$$
注意分母是**请求数量**，**起始磁头位置不算一个请求**

---

# 四、FCFS：先来先服务

按照请求到达顺序访问，不重新排序

假设：

```
初始磁头：50
请求序列：10，60，20，80
```

执行顺序：

```
50 → 10 → 60 → 20 → 80
```

总移动距离：

**∣50−10∣+∣10−60∣+∣60−20∣+∣20−80∣= 40+50+40+60=190**

平均：190/4=47.5

### 优缺点

- 优点：简单、公平，==**不会饥饿**==
- 缺点：磁头可能剧烈来回移动，平均寻道距离大，**性能差**

一句话：

> **FCFS 看时间顺序，不看磁道位置**

---

# 五、SSTF：最短寻道时间优先

每次选择离当前磁头**最近**的请求

仍然是：

```
初始：50
请求：10，60，20，80
```

从 50 开始：

- 离 60 最近，先访问 60；
- 当前 60，离 80 最近；
- 当前 80，剩下 20、10，先访问 20；
- 最后访问 10

顺序：

```
50 → 60 → 80 → 20 → 10
```

### 核心规则

> 每完成一次访问，都必须以新的磁头位置重新计算最近请求

不能只在开头排一次序

### 优缺点

- 优点：通常比 FCFS 的平均寻道距离短
- 缺点：可能产生**饥饿**

例如磁头附近不断出现新请求，远处请求可能一直得不到处理

### “磁臂粘着”

如果某一区域请求特别密集，SSTF 可能长期停留在该区域附近，不愿意离开

---

# 六、SCAN：扫描算法

也叫**电梯算法**

磁头先沿一个固定方向移动，处理该方向上所有请求，到达一端后再反向

例如：

```
当前磁头：50
之前从40移动到50
请求：10，20，60，80
```

因为之前是：

```
40 → 50
```

**说明磁头正向磁道号增加方向移动**

所以先处理：

```
60 → 80
```

再反向：

```
20 → 10
```

最终：

```
50 → 60 → 80 → 20 → 10
```

### 如何判断初始方向

题目经常这样给：

```
当前磁头在90
此前刚访问93
```

说明：

```
93 → 90
```

所以当前方向是**磁道号减小方向**

这是常见得分点

### 优缺点

- 不容易饥饿；
- 平均寻道距离较好；
- **“磁臂粘着”现象仍未解决**：**刚错过磁头的请求可能要等磁头完成整次往返**

---

# 七、C-SCAN：循环扫描算法

SCAN 像电梯上下运行：

```
向上服务 → 向下服务 → 向上服务
```

**C-SCAN 则只在一个方向上提供服务**：

```
一直向上服务
→ 到顶端后直接回到底端
→ 再继续向上服务
```

返回过程中不处理请求

例如磁头向磁道号增加方向：

```
当前：50
请求：10，20，60，80
```

执行：

```
50 → 60 → 80
```

然后跳到低端，从低端继续：

```
10 → 20
```

完整顺序：

```
50 → 60 → 80 → 10 → 20
```

### 为什么有 C-SCAN

SCAN 中：

- 中间磁道经常被双向经过；
- **两端请求的等待时间可能不均衡**

C-SCAN 让所有请求都等待一次单向扫描，等待时间更加均匀

### 注意

**从最高端跳到最低端的移动距离，计算总寻道距离时通常也要算**


---

# 八、四种算法一张表

| 算法     | 选择规则          | 是否需要方向 | 优点      | 主要缺点    |
| ------ | ------------- | ------ | ------- | ------- |
| FCFS   | 按到达顺序         | 否      | 简单、公平   | 寻道距离大   |
| SSTF   | 每次选最近请求       | 否      | 平均距离较短  | 可能饥饿+久等 |
| SCAN   | 沿当前方向依次服务，再反向 | 是      | 公平性较好   | 刚错过要久等  |
| C-SCAN | 只沿固定方向服务，循环返回 | 是      | 等待时间更均匀 | 返回距离较大  |

记忆：

```
FCFS：按队列
SSTF：找最近
SCAN：来回扫
C-SCAN：单向循环扫
```
