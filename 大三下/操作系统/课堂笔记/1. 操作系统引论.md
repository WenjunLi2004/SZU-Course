## 预习
### 操作系统的目标

**疑问：难道计算机可以没有操作系统吗？**
- 其实是可以的，人工操作硬件：用户独占全机，CPU等待人工操作

- **方便性**：​没有OS，你想打开一个文档文件，需要**自己写驱动**去读硬盘、解析文件格式、驱动显卡显示像素。OS提供了图形界面、文件管理、命令解释器等，让普通人也能轻松使用计算机。
    
- **有效性**​ ：没有OS，内存如何分配给多个程序？CPU如何在多个任务间切换？外设谁先用谁后用？OS作为“大管家”，统一管理和调度所有硬件资源（CPU、内存、硬盘、网络等），让它们高效、合理地协同工作，避免冲突和浪费
    
- **可扩充性**​ ：没有OS，每增加一个新硬件（比如新型号的显卡），所有软件都可能需要重写来适配它。OS提供了标准的驱动接口，硬件厂商只需提供针对OS的驱动，所有应用软件就都能使用它
    
- **开放性**​ ：没有OS，每个软件开发商都要为一台计算机单独开发，没有通用标准。OS定义了应用程序和计算机交互的标准接口（API），使得软件可以在遵循同一标准的任何计算机上运行，实现了软硬件的解耦和生态繁荣

### OS 发展

1. 从人工操作硬件发展到**脱机输入/输出**(Off-Line I/O)方式
	- 增加一个额外的硬件脱离主机来处理输入和输出，从而减少了CPU的空闲时间和提高I/O效率
2. 进一步发展到早期的批处理操作系统：单通道 -> 多通道，分为 Input - Execute - Output 
	-  资源利用率高，吞吐量大
	**面临的问题：并发和资源共享引发的管理难题**
	1. **处理机管理问题**（谁该用CPU？用多久？）
	2. **内存管理问题**（程序放哪？互不干扰？）
	3. **I/O设备管理问题**（谁先用打印机？）
	4. **文件管理问题**（数据如何组织、保护？）
	5. **作业管理问题**（如何组织作业流？）

所以**操作系统的定义** ： 一组 **控制和管理**计算机硬件和软件资源，合理对各类作业进行调度 ，方便用户使用 的 **程序的集合**

它不是一个单一的程序，而是由许多模块化、各司其职的程序共同构成的，例如：
- **内核**​：最核心的部分，负责管理CPU、内存、进程等关键资源。它通常不是一个可以直接运行的“应用”，而是为其他程序提供服务的底层基础
    
- **系统程序**：例如用于文件操作的命令（`cp`, `mv`）、用于进程查看的命令（`ps`）、Shell（命令解释器）等
    
- **驱动程序**​ ：用于和特定硬件（如显卡、声卡）通信的特殊程序
    
- **用户接口程序**​：如图形界面（GUI）的窗口管理器、桌面环境等

#### 两条发展路径

1. **解决效率问题**
	1. **多道批处理系统**：实现了自动调度和资源管理，但缺乏交互性(用户提交作业后只能等待)
	2. **分时系统**：引入了 **==“时间片”==** 概念
	   CPU时间切成极小的片段，轮流分配给多个联机用户。由于切换速度极快，每个用户都感觉自己在独占主机
	3. **实时系统**：在分时系统“及时”的基础上，对“时间”的要求达到了**严格、可预测的级别**

2. **普及到个人**
	1. **单用户单任务（如MS-DOS）**：这是操作系统理念的“简化版”或“回溯”。由于早期微机性能极弱，它只实现了最基础的**文件管理**和**设备驱动**，没有分时多任务能力
	   **用户一次只能运行一个程序，命令行操作**
	2. **单用户多任务（如Windows系列、经典Mac OS）**：**分时系统思想**在个人电脑上的实现
	3. **多用户多任务（如Unix、Linux及衍生的macOS）**：**完整的分时系统**在服务器和高端工作站上的体现
	   **多个用户能够同时、独立地使用同一台计算机**：每个用户拥有自己的账户、文件、设置和运行环境，操作系统负责安全地隔离和管理这些资源，确保彼此互不干扰—— ==**并发**==
### 操作系统四大基本特性

1. **并发 Concurrence**：多核并行，单核并发——宏观上多个程序在同时运行，微观上分时交替执行
2. **共享 Sharing**：系统资源（内存、CPU、设备等）供内存中多个并发执行的程序共同使用
3. **虚拟 Virtual**：通过技术将物理实体变为逻辑上的对应物（如虚拟内存），方便用户使用
4. **异步性 Asynchronism**：进程以不可预知的速度向前推进，**允许程序在运行中被中断**
