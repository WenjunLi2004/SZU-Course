## 1. 基本分段存储管理：为什么要分段？

### 1.1 形象理解

分页像是宿舍管理员为了方便管理，把内存切成等大的床位：

```text
第 0 页、第 1 页、第 2 页……
```

它关心的是：

```text
这一页放到哪个物理块？
```

但程序员写程序时，脑子里并不是一堆等大的页，而是：

```text
main 函数在哪？
全局变量在哪？
栈在哪？
堆在哪？
共享库代码在哪？
```

所以分段更像是按照**程序的逻辑结构**来划分：

```text
代码段
数据段
堆段
栈段
子程序段
共享库段
```

### 1.2 严谨定义

**分段存储管理**：把一个进程划分为多个具有==**逻辑意义**==、相对独立的部分
常见段包括**主程序段、数据段、堆栈段、子程序段**等。

每个段都有自己的**独立逻辑地址空间**，并且==每个段内部都从 0 开始编号==

---

## 2. 分段地址为什么说是二维地址？

### 2.1 分段地址结构

分段逻辑地址通常写成：

```text
(段号, 段内地址)
```

例如：

```text
(2, 895)
```

含义是：

```text
访问第 2 段中偏移量为 895 的位置
```

这里必须同时==**显式说明**==两个信息：

```text
访问哪个段？
访问该段内部的哪个位置？
```

**所以分段地址空间是二维的**

### 2.2 分页地址看起来也是二维，为什么是一维？

分页地址在硬件转换时确实会被拆成：

```text
页号 + 页内地址
```

但是分页中的页号和页内地址是==**系统根据线性地址自动算出来的**==：

```text
页号 P = A / page_size
页内地址 d = A % page_size
```

也就是说**不需要显式写**：

```text
(页号, 页内地址)
```

所以：

```text
分页：逻辑地址本质是一维线性地址，只是系统内部拆成页号和页内地址
分段：逻辑地址本身就是二维的，需要显式说明段号和段内地址
```

---

## 3. 段表：分段地址变换的核心

### 3.1 段表中记录什么？

分页系统中，页表主要记录：页号 -> 物理块号

分段系统中，段表主要记录：

```text
段号 -> 段长 + 段基址
```

**典型段表：**

| 段号 | 段长 | 段基址 |
|---|---:|---:|
| 0 | 30K | 40K |
| 1 | 20K | 80K |
| 2 | 15K | 120K |
| 3 | 10K | 150K |

### 3.2 为什么段表必须有“段长”？

**因为段的长度不固定**

例如：

```text
代码段：30K
数据段：20K
栈段：10K
```

系统必须知道每个段的合法范围，否则无法判断段内地址是否越界

而分页不需要在每个页表项里记录页长，因为：

```c
page size = frame size
```

**所有页大小相同，所有物理块大小也相同**

所以：

- **页不需要记录页长，因为所有页一样长**
- **段必须记录段长，因为每个段可能不一样长**

---

## 4. 分段地址变换过程

假设 CPU 给出逻辑地址：

```text
(s, w)
```

其中：

```text
s = 段号
w = 段内地址，也叫段内位移量
```

地址变换过程：

```text
1. 取出段号 s
2. 检查 s 是否超过段表长度
3. 如果段号合法，查段表，得到该段的段长 limit 和段基址 base
4. 检查段内地址 w 是否超过段长
5. 如果段内地址合法，物理地址 = base + w
6. 根据物理地址访问内存
```

公式：

```text
物理地址 = 段基址 + 段内地址
```

**越界判断要严谨**：

```text
合法条件：0 <= w < 段长
越界条件：w >= 段长
```

如果某段段长为 1000，那么合法段内地址是：

```v
0 ~ 999
```

所以：

```v
w = 999  合法
w = 1000 越界
```

---

## 5. 段号越界、段内越界、缺段的区别

1. **段号越界**：访问的段号 >= 段表长度

2. **段内越界**：段内偏移量超过该段长度

> 非常易错：段内地址 >= 段长，基址占了一个

3. **缺段**：段号和段号地址都合法，但当前不在内存
- 发生在请求分段存储管理

## 6. 分段的优点

### 6.1 方便编程

程序员天然按照模块理解程序：

```text
主程序段
子程序段
数据段
栈段
堆段
```

分段更符合程序结构

### 6.2 信息共享

段是有意义的逻辑单位，因此**共享更自然**

例如多个进程都使用同一个编辑器代码段或动态链接库代码段，可以让它们的段表指向同一个物理段

```text
进程 A 的 editor 段 -> 物理内存中的 editor 代码
进程 B 的 editor 段 -> 同一段 editor 代码
```

这样不需要每个进程都复制一份相同代码

### 6.3 信息保护

因为段有逻辑含义，所以可以按段设置权限：

```shell
代码段：只读、只执行
数据段：可读写
栈段：可读写，可动态增长
共享库代码段：只读、可执行、可共享
```

这比分页更符合程序员的理解

### 6.4 动态增长

堆和栈都可能在运行时增长，分段可以让某些段独立扩展。

### 6.5 动态链接

动态库可以作为独立段，在程序运行过程中被装入、链接和共享

---

## 7. 分页与分段的区别

| 对比点  | 分页                       | 分段                  |
| ---- | ------------------------ | ------------------- |
| 划分目的 | 方便操作系统管理内存               | 符合用户程序的逻辑结构         |
| 单位性质 | 信息的物理管理单位                | 信息的==**逻辑单位**==     |
| 大小   | **固定，由系统决定**             | **不固定，由程序逻辑决定**     |
| 地址结构 | **一维**线性地址，系统自动拆成页号和页内地址 | **二维**地址，段号 + 段内地址  |
| 表项内容 | 页号 -> 物理块号               | 段号 -> 段长 + 段基址      |
| 内存分配 | 页可以离散放入不同物理块             | ==**每个段通常需要连续空间**== |
| 碎片问题 | 主要有内部碎片                  | 容易产生外部碎片            |
| 共享保护 | 可以实现，但语义不如分段自然           | 很自然，因为段有逻辑意义        |

核心记忆：

```text
分页：系统视角，解决内存分配效率问题
分段：用户视角，解决程序逻辑表达、共享和保护问题
```

---

## 8. 分段的缺点：为什么还要引入段页式？

分段虽然符合程序逻辑，但它一个很大的问题：

```text
每个段在物理内存中通常需要连续空间
```

**例如一个段长 20K，系统必须找到一整块连续的 20K 空闲内存**

**这会重新带来连续分配的问题**：

```text
外部碎片
空闲区合并
总空闲空间够，但没有足够大的连续空间
```

所以引入段页式管理

---

## 9. 段页式管理：先分段，再分页

### 9.1 核心思想

段页式管理结合了分段和分页的优点：

```shell
1. 先把程序划分成多个有逻辑意义的段
2. 再把每个段划分成大小相等的页
3. 最后把这些页离散装入物理块
```

所以它可以理解为：

```text
段页式 = 分段的逻辑结构 + 分页的离散分配
```

更具体地说：

```text
分段：保留程序逻辑意义，方便共享、保护、动态链接
分页：解决段必须连续分配的问题，提高内存利用率
```

### 9.2 段页式解决了什么？

分段的问题：

```text
段长不固定，段需要连续分配，容易产生外部碎片
```

分页的优点：

```text
页大小固定，可以离散放入任意物理块
```

段页式的做法：

```text
每个段内部再分页
```

这样一个段不需要连续放在内存中，段内的各个页可以分散放入不同物理块。

---

## 10. 段页式地址结构

段页式逻辑地址通常可以看成三部分：

```text
段号 S + 段内页号 P + 页内地址 W
```

也可以理解为：

```text
(段号, 段内地址)
```

其中段内地址再拆成：**段内页号 + 页内地址**

如果页面大小为 L，段内地址为 d，那么：

```text
段内页号 P = d / L
页内地址 W = d % L
```

---

## 11. 段页式中的段表和页表

### 11.1 基本结构

段页式需要同时设置：**段表和页表**

**特殊的是**：

```text
每个段都有自己的一张页表
```

段表中不再直接记录段的物理基址，而是记录：

- ==**段号 -> 该段页表的起始地址 + 该段页表长度**==

每个段的页表再记录：

```text
段内页号 -> 物理块号
```

---

## 12. 段页式地址变换过程

逻辑地址为：(S, P, W)
```text
S = 段号
P = 段内页号
W = 页内地址
```

地址变换过程：

```v
1. 取得段号 S
2. 检查段号是否越界
3. 查段表，得到该段页表的开始地址和页表长度
4. 检查段内页号 P 是否超过该段页表长度
5. 查该段页表，得到物理块号 B
6. 页内地址 W 直接对应块内地址
7. 物理地址 = B * 页面大小 + W
8. 根据物理地址访问内存
```

核心公式：

```text
物理地址 = 物理块号 × 页面大小 + 页内地址
```

整体关系：

```text
段号 S
  ↓ 查段表
该段页表起始地址
  ↓ 查段内页表
段内页号 P -> 物理块号 B
  ↓
物理地址 = B * page_size + 页内地址 W
```
---

## 13. 段页式：三次内存

在没有快表的情况下，段页式一次访问数据通常需要访问三次内存：

```text
第一次：访问段表，找到该段对应页表的位置
第二次：访问页表，找到段内页对应的物理块号
第三次：访问实际数据
```

所以：

```text
分段：段表 + 数据，通常 2 次内存访问
分页：页表 + 数据，通常 2 次内存访问
段页式：段表 + 页表 + 数据，通常 3 次内存访问
```

**段页式结构更灵活，但地址变换开销更大**

---

## 14. 段页式中的快表

为了减少地址变换开销，可以加入快表

**段页式快表的查找关键字通常不是单独的页号**，而是**直接 (段号, 段内页号)**

快表项记录：

```text
(段号, 段内页号) -> 物理块号
```

如果快表命中：

```text
直接得到物理块号
物理地址 = 物理块号 × 页面大小 + 页内地址
```

如果快表未命中：

```text
再执行三次访问
```

---

## 15. 段页式与分页、分段的对比

| 对比点 | 分页 | 分段 | 段页式 |
|---|---|---|---|
| 逻辑结构 | 一维线性空间 | 多个逻辑段 | 先分段，再分页 |
| 内存分配 | 页离散分配 | 段通常连续分配 | 段内页离散分配 |
| 是否符合程序逻辑 | 弱 | 强 | 强 |
| 是否减少外部碎片 | 是 | 否 | 是 |
| 是否有内部碎片 | 有，最后一页可能不满 | 通常无内部碎片 | 有，段内最后一页可能不满 |
| 表结构 | 一个页表 | 一个段表 | 一个段表 + 多个页表 |
| 地址结构 | 页号 + 页内地址 | 段号 + 段内地址 | 段号 + 段内页号 + 页内地址 |
| 地址变换次数 | 页表 + 数据 | 段表 + 数据 | 段表 + 页表 + 数据 |
| 快表关键字 | 页号 | 段号 | 段号 + 页号 |

## 16. 段页式计算题模板

### 16.1 已知逻辑地址为 `(S, d)`

如果题目给出的是：

```text
段号 S
段内地址 d
页面大小 L
```

先把段内地址拆成：

```text
段内页号 P = d / L
页内地址 W = d % L
```

然后：

```text
查段表：S -> 该段页表首址
查该段页表：P -> 物理块号 B
物理地址 = B × L + W
```

### 16.2 已知逻辑地址为 `(S, P, W)`

如果题目已经直接给出：

```text
段号 S
段内页号 P
页内地址 W
```

则直接：

```text
查段表：S -> 该段页表首址
查页表：P -> 物理块号 B
物理地址 = B × page_size + W
```

## 17. 例题：段页式地址计算

题目：

```text
页面大小 = 1024 字节
逻辑地址 = (1, 2099)
```

这里可以理解为：

```text
段号 = 1
段内地址 = 2099
```

先拆段内地址：

```text
段内页号 = 2099 / 1024 = 2
页内地址 = 2099 % 1024 = 51
```

如果段表中：

```text
段号 1 -> 页表首址为 33
```

并且段 1 的页表中：

```text
页号 2 -> 内存块号 40
```

那么：

```text
物理地址 = 40 × 1024 + 51 = 41011
```

## 19. 我的理解

分段和分页不是简单的“谁更高级”，它们解决的问题不同。

分页是从操作系统角度出发的。它把逻辑空间切成等大的页，把物理内存切成等大的块，从而让内存可以离散分配，减少外部碎片，提高内存利用率。

分段是从程序员和程序逻辑角度出发的。程序天然有代码、数据、堆、栈、库函数等不同逻辑部分。分段让这些逻辑部分可以独立管理、共享、保护和增长。

段页式则是二者的结合：先用分段保留程序的逻辑结构，再用分页解决分段连续分配带来的外部碎片问题。

一句话总结：

```text
分页解决“内存怎么高效分”；
分段解决“程序怎么有意义地组织”；
段页式解决“既要逻辑清晰，又要内存高效”。
```

## 20. 常见误区

### 20.1 误区：分页也拆成页号和页内地址，所以分页也是二维地址

分页内部确实拆成两个字段，但它的逻辑地址空间本质仍是一条线性地址。页号是系统根据页大小自动算出来的。

分段则要求逻辑地址显式包含段号和段内地址，因此说分段是二维地址。

### 20.2 误区：段号越界就是缺段

不是。

段号越界表示这个段根本不是该进程的合法段。

缺段表示段合法，但当前没有调入内存。

### 20.3 误区：段内地址等于段长也合法

不合法。

如果段长为 1000，合法地址是：

```text
0 ~ 999
```

所以：

```text
段内地址 < 段长      合法
段内地址 >= 段长     越界
```

### 20.4 误区：段页式就是分页多加了一个段号

不够准确。

段页式不是简单多一个字段，而是：

```text
先按逻辑意义分段
再对每个段分页
每个段都有自己的页表
```

### 20.5 误区：段页式没有碎片

段页式可以减少分段带来的外部碎片，但仍可能有内部碎片。

因为每个段最后一页可能装不满。

### 20.6 误区：段页式地址变换只查一次表

段页式至少要查两级结构：

```text
段表
页表
```

然后才能访问数据。

没有快表时，一次数据访问通常需要三次内存访问：

```text
段表 + 页表 + 数据
```

## 21. 自测题

### 21.1 分段地址计算

某段表如下：

| 段号 | 段长 | 基址 |
|---|---:|---:|
| 0 | 500 | 2000 |
| 1 | 1000 | 8000 |
| 2 | 300 | 12000 |

判断并计算：

```text
A = (1, 999)
B = (1, 1000)
C = (3, 10)
```

答案：

>[!note]+ Answer
> A 合法，物理地址 = 8000 + 999 = 8999
> B 段内地址越界，因为 1000 >= 1000
> C 段号越界，因为段号 3 不存在

### 21.2 段页式地址计算
