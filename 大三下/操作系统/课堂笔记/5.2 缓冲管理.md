## 1. 为什么需要缓冲区

假设磁盘向内存输入数据，而用户进程对数据进行计算

没有缓冲时，双方需要直接交接：

```
设备准备数据 → 等进程接收
进程处理数据 → 等设备准备下一批
```

**设备与进程容易互相等待，效率低下**

缓冲区相当于放在二者之间的“中转仓库”：

```
I/O设备 → 缓冲区 → 用户进程工作区
```

三个引入缓冲的原因：

1. 缓和 CPU 与 I/O 设备**速度不匹配**的矛盾
2. 减少 CPU 中断频率，放宽中断响应时间
3. 提高 CPU 与 I/O 设备之间的**并行性**

### 一个重要结论

缓冲只能**缓和**速度矛盾，不能永久消除速度差

例如键盘偶尔快速输入一串字符，缓冲区可以暂存但如果设备长期产生数据的速度高于进程处理速度，再大的有限缓冲区最终也会装满

# 二、计算题中的三个时间

公式使用三个符号：

- `T`：**I/O 设备** --- **一块数据** --> ==**输入**==缓冲区的时间
- `M`：把数据从 **缓冲区-- ==输入== -->用户工作区** 的时间
- `C`：用户进程处理这块数据的时间

==**数据流程**==：

```
I/O设备 --T--> 缓冲区 --M--> 工作区 --C--> 处理完成
```

下面所有公式通常讨论连续处理许多块数据时，**稳定阶段每处理一块数据的周期**

---

# 三、单缓冲

系统只设置一个缓冲区：

```
I/O设备 → 唯一缓冲区 → 用户工作区
```

## 运行过程

对第一块数据：

```
输入到缓冲区 T→ 搬到工作区 M→ 用户处理 C
```

当用户处理第一块数据时，缓冲区已经空出来，因此设备可以同时输入第二块数据

**输入 T 和处理 C 并行**：两个不同的数组
```
处理第1块 C + 输入第2块 T
```


**输出 M 同时使用两个数组**：缓冲区向工作区搬运数据的 `M` 阶段，必须等**设备停止使用缓冲区**、并且**用户上一块处理完成**后才能进行

> M相当于读取数据，C和T都是写入

所以每块数据的==**稳定周期**==是：$max⁡(C,T)+M​$

## 为什么取最大值

因为 `C` 和下一次 `T` 同时开始：

```
设备：输入下一块，花 T
进程：处理当前块，花 C
```

要等两者都完成，才能进行下一次 `M`，所以等待时间由更慢的那个决定：

```
max(C,T)
```

然后还要加上传送时间 `M`

## 例题

假设：

```
T = 8 ms
M = 2 ms
C = 5 ms
```

则单缓冲周期为：max⁡(5,8)+2=10 ms

设备输入比计算慢，因此**主要瓶颈是输入**

# 四、双缓冲

**设置两个缓冲区使得 M可以和输入C并行**

工作方式类似乒乓球：

1. 设备向缓冲区 1 输入
2. 缓冲区 1 满后，设备立刻转向缓冲区 2
3. 与此同时，进程从缓冲区 1 搬数据并处理
4. **两个缓冲区轮流使用**

示意：

```
时间段1：
设备 → 缓冲1

时间段2：
设备 → 缓冲2
缓冲1 → 工作区 → 处理

时间段3：
设备 → 缓冲1
缓冲2 → 工作区 → 处理
```

这一次，设备的输入 `T` 可以和主机的整个：

```
M + C
```

过程重叠

所以双缓冲周期为：$max⁡(T,C+M)$


## 两种情况

### 情况一：`C + M < T`

主机处理得更快：

```
主机处理完了→ 设备还没输入完→ 主机等待设备
```

设备可以连续输入，**瓶颈是设备**

### 情况二：`C + M > T`

设备输入得更快：

```
设备填满一个缓冲区
→ 主机还没处理完另一个
→ 设备等待空缓冲区
```

主机可以连续处理，**瓶颈是主机**

---

# 五、单缓冲与双缓冲对比

仍使用：

```
T = 8 ms
M = 2 ms
C = 5 ms
```

单缓冲：msmax(C,T)+M=max(5,8)+2=10 ms

双缓冲：max(C+M,T)=max(7,8)=8 ms

双缓冲更快，是因为 `M` 也被隐藏在与设备输入的并行过程中了

但注意，**并不是所有数据下双缓冲都能显著变快**

例如：

```
T = 3 M = 2 C = 20
```

单缓冲：max(20,3)+2=22

双缓冲：max(22,3)=22

因为计算时间远大于输入时间，瓶颈完全在用户进程，增加缓冲区无法突破计算瓶颈

# 六、循环缓冲

如果两个缓冲区仍然不够，可以设置多个缓冲区并首尾相连：

```
B0 → B1 → B2 → B3 → B0
```

![[Pasted image 20260624230904.png]]

循环缓冲区分为三种状态：

- **空缓冲区**：可以写入
- **装满缓冲区**：已经有数据，等待取走
- **执行缓冲区**：当前正在被使用

对应三个指针：

- `Nexti`：输入进程接下来使用的空缓冲区
- `Nextg`：计算进程接下来取得的满缓冲区
- `current`：当前正在处理的缓冲区

可以把它理解成生产者—消费者问题：

```
I/O设备 = 生产者
用户进程 = 消费者
循环缓冲区 = 有界缓冲池
```

## 两种必须阻塞的情况

### 输入追上输出

设备写得太快，所有缓冲区都满了：

```
Nexti 追上 Nextg
```

生产者必须等待消费者释放缓冲区

### 输出追上输入

进程取得太快，没有新的满缓冲区：

```
Nextg 追上 Nexti
```

消费者必须等待设备输入新数据

因此循环缓冲不仅是数组和指针问题，也包含进程同步问题

# 七、缓冲池

循环缓冲通常主要服务于==**设备单向输入**==，而缓冲池进一步把==**输入和输出**==统一起来

同理，也是三种状态
### 三种缓冲区

- 空闲缓冲区
- 装有输入数据的缓冲区
- 装有输出数据的缓冲区

### 三个队列

- 空缓冲队列
- 输入队列
- 输出队列

### 四种操作

| 操作          | 含义               |
| ----------- | ---------------- |
| 收容输入 `hin`  | 设备取得空缓冲区，将输入数据放入 |
| 提取输入 `sin`  | 用户进程从输入队列取得数据    |
| 收容输出 `hout` | 用户进程将输出数据放入缓冲区   |
| 提取输出 `sout` | 输出设备从输出队列取得数据    |


**完整流程：**

```
输入方向：
空缓冲队列
→ hin：设备写入
→ 输入队列
→ sin：用户读取
→ 回到空缓冲队列
```

```
输出方向：
空缓冲队列
→ hout：用户写入
→ 输出队列
→ sout：设备输出
→ 回到空缓冲队列
```

# 八、本节最需要记住的内容

## 作用

> **缓和速度矛盾、减少中断、提高并行性**

## 公式

单缓冲周期=max⁡(C,T)+M
双缓冲周期=max⁡(C+M,T)

## 演进关系

```
单缓冲
→ 只有一个中转站

双缓冲
→ 两个中转站轮换，实现更充分并行

循环缓冲
→ 多个中转站构成环形队列

缓冲池
→ 用多个队列统一管理输入和输出缓冲区
```
