## 一、设备管理到底在解决什么问题

CPU 和内存都很快，但键盘、打印机、磁盘等设备：

- 种类不同
- 速度差距很大
- 控制方法不同
- 多个进程可能同时请求
- CPU 不应该一直亲自等待设备

因此设备管理要完成三个核心任务：

> **让进程方便地使用设备，让 CPU 少等待，让设备尽量忙起来**

主要功能包括：缓冲区管理、设备分配、设备处理、虚拟设备以及设备独立性 ...

可以把第五章看成一条数据运输链：

```
用户进程
   ↓ I/O请求
操作系统I/O软件
   ↓
CPU / 内存
   ↓
I/O通道
   ↓
设备控制器
   ↓
具体I/O设备
```


- **设备管理**关心数据“怎么搬运”
- **文件系统**关心数据“叫什么、怎么组织、放在哪里”

例如读取 `/home/a.txt`：

1. 文件系统根据路径找到文件的数据块
2. 设备管理控制磁盘把这些数据块读入内存

## 二、I/O 设备的三种分类

### 1. 按传输速率

**低速、中速和高速**

例如键盘、鼠标属于低速设备，磁盘属于高速设备

考试通常只要求知道分类思想，不必死记具体速率

### 2. 按信息交换单位

这是更重要的分类

| 类型   | 数据单位   | 是否可寻址    | 典型设备     | 常见控制方式 |
| ---- | ------ | -------- | -------- | ------ |
| 块设备  | 数据块    | 可以随机访问   | 磁盘       | DMA    |
| 字符设备 | 字符或字节流 | 通常不可随机寻址 | 键盘、鼠标、串口 | 中断驱动   |

#### 块设备

磁盘被划分为一个个数据块，可以直接要求：

```
读取第 1000 个块
```

不需要从第一个块开始顺序读

#### 字符设备

键盘产生的是连续字符流：

```
h → e → l → l → o
```

通常不能要求“读取键盘中的第 1000 个字符”

### 3. 按共享属性

- **独占设备**：某段时间只能由一个进程使用，如传统打印机
- **共享设备**：多个进程可以交替、并发访问，如磁盘
- **虚拟设备**：利用软件技术，把一台物理设备表现成多台逻辑设备

后面的 **SPOOLing**，就是把独占的打印机改造成逻辑上的共享设备

## 三、设备控制器与 I/O 通道

这两个概念很容易混淆

### 1. 设备控制器：直接管理设备

CPU 一般不会直接控制磁头、打印针、电机等具体部件，而是**向设备控制器发送命令**

设备控制器可以理解为设备的“现场主管”：

```
CPU：读取磁盘第100块
控制器：控制磁头、等待旋转、读取扇区、检查错误
```

它负责：

- 接收 CPU 或通道的命令
- 控制具体设备
- 暂存数据
- 报告设备状态
- 在设备完成后产生中断

所以：

> **设备控制器是 CPU 与具体 I/O 设备之间的硬件接口**

一个控制器可以连接一个或多个设备

## 2. I/O 通道：专门处理 I/O 的小处理机

通道比控制器层次更高它是一种特殊处理机：

- 能执行 I/O 指令
- 能执行一段“通道程序”
- 可以管理控制器和多个设备
- 没有自己的内存，通道程序放在主存中

它相当于 CPU 的“I/O 助理”：

```
CPU：这是通道程序地址，你照着执行
通道：负责后续多个数据块的读写
CPU：继续运行其他程序
```

==**完整通路：通道 → 控制器 → I/O设备**==



==**多通路系统**==会为设备提供多条可选路径，避免某个通道或控制器故障后设备完全不可用

### 一句话区分

> **控制器直接控制设备通道负责执行 I/O 程序并管理控制器**

### 四、四种 I/O 控制方式

**这部分是第五章最重要的概念题**

发展方向是：

```
程序查询 → 中断驱动 → DMA → I/O通道
```

本质上是：

> **CPU 参与得越来越少，I/O 系统自主能力越来越强**

## 1. 程序 I/O：CPU 一直询问

也叫程序查询方式、==**轮询**==方式

过程：

```
CPU向设备发命令
→ 查询设备是否完成
→ 没完成，再查询
→ 仍没完成，继续查询
→ 完成后传送数据
```

### 缺点

设备很慢，CPU 却一直==**忙等待**==：

```
CPU：好了吗？
设备：没有
CPU：好了吗？
设备：没有
```

CPU 无法有效执行其他进程，**利用率很低**

---

## 2. 中断驱动 I/O：设备完成后通知 CPU

CPU 启动设备后，不再持续查询，而是运行其他程序

```
CPU启动I/O
→ CPU执行其他进程
→ 设备准备好
→ 设备发出 <中断>
→ CPU执行中断处理程序
→ 传送一个字符或数据单位
```

### 优点

消除了 CPU 的忙等

### 缺点

如果设备每传送一个字符或一个数据单位都中断一次，CPU 仍然需要频繁：

- **保存现场**
- **执行中断处理程序**
- **传送数据**
- **恢复现场**

因此，**中断驱动适合键盘等低速字符设备**，但大批量磁盘传输会产生较大中断开销

---

## 3. DMA：数据直接在设备和内存之间传输

DMA 全称：

> **Direct Memory Access，直接存储器访问**

CPU 只需告诉 DMA 控制器：

- 从哪个设备传输
- 内存起始地址
- 传输方向
- 传输多少数据

随后数据直接传送：

```
设备 ⇄ 内存
```

而不是：

```
设备 → CPU寄存器 → 内存
```

传输完成后，DMA 再中断 CPU 一次

### 过程

```
CPU设置DMA参数
→ DMA接管总线
→ DMA传送整个数据块
→ 完成后中断CPU
```

### 核心特点

- 以**数据块**为单位
- 实际传输过程不需要 CPU 逐字处理
- CPU 只负责初始化和完成处理
- 适合磁盘等高速块设备

### 容易出错的说法

错误：

> DMA 工作期间完全不使用系统总线

正确：

> **DMA 仍需使用内存总线访问主存，只是不需要 CPU 执行每一次数据搬运**

DMA 与 CPU 可能产生总线竞争，DMA 可采用周期窃取等方式获得总线控制权

---

## 4. I/O 通道：执行完整的通道程序

DMA 虽然能传输一个数据块，但 CPU 仍要为每次 DMA 操作设置：

- **设备**
- **内存地址**
- **字节数**
- **读写方向**

**如果有很多设备，CPU 还是要频繁配置 DMA，引入了通道**

通道可以理解成“**专门负责 I/O 的小 CPU**”，进一步提高了自主性，CPU 只需要**给出一次**：

- ==**通道程序**==首地址
- 要访问的设备

随后通道==**自行执行**==多条 I/O 指令，完成一组数据块的读写

**通道控制方式可以实现 CPU、通道和 I/O 设备三者并行工作**

## 五、四种方式对比

|控制方式|CPU 是否忙等|数据传输单位|数据是否逐个经过 CPU|CPU 干预频率|
|---|---|---|---|---|
|程序 I/O|是|字或字符|是|最高|
|中断驱动|否|字或字符|是|每个数据单位或事件|
|DMA|否|数据块|否|每个数据块|
|I/O 通道|否|一组数据块或完整 I/O 任务|否|最低|

记忆口诀：

> **程序方式一直等，中断方式完成叫DMA 搬一整块，通道执行一套程序**

发展规律：
1. **早期计算机里，设备根本没有能力直接访问内存，设备只能和 CPU 说话**
2. **DMA 控制器拥有总线控制权，可以直接在设备和内存之间传输数据**

```
CPU干预程度：程序I/O > 中断驱动 > DMA > 通道
并行程度：   程序I/O < 中断驱动 < DMA < 通道
硬件复杂度： 程序I/O < 中断驱动 < DMA < 通道
```

## 六、常见误区

### 误区一：中断驱动后，CPU 完全不参与数据传输

不对中断驱动中，CPU 通常还需要执行中断处理程序，完成数据寄存器与内存间的数据传送

### 误区二：DMA 就是 I/O 通道

不对

- DMA 主要负责**一个数据块的直接传输**
- 通道能执行**多条 I/O 指令组成的通道程序**

### 误区三：控制器和通道是同一个东西

不对

```
通道：执行I/O程序、管理控制器
控制器：直接控制具体设备
```

### 误区四：虚拟设备是虚拟机中的设备

这里的虚拟设备是指通过 SPOOLing 等技术，把一台独占物理设备虚拟成多台逻辑设备
