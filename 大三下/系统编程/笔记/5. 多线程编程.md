## 1. 为什么要有线程

### 1.1 进程的不足

前两章我们学的是**进程模型**：

- 进程是程序运行的一个实例
- 进程之间默认**地址空间隔离**
- **进程间通信需要额外机制**，例如 `pipe`、`FIFO`、`signal` 等 IPC

进程模型的优点是隔离性强，但也有明显不足：

| 问题 | 解释 |
|---|---|
| 创建成本较高 | `fork()` 需要创建新的进程控制结构，并建立新的地址空间视图 |
| 通信成本较高 | 进程不能直接访问对方变量，通常需要经过内核或 IPC |
| 协作不够轻便 | 如果只是让同一程序内部并发执行，用多个进程会显得重 |

线程的引入，就是为了在**同一个进程内部**创建多个执行流：

- 多个线程==**共享同一进程的大部分资源**==
- 每个线程又有自己的==**执行现场**==
- 因此，线程比进程更适合轻量级并发任务

> [!important]+ 核心转换
> **进程：默认隔离，通信需要额外设计**  
> **线程：默认共享，安全需要额外设计**
### 常见误区

- ==误区 1：线程就是更小的进程==  
  线程不是完整的资源分配单位，而是同一进程内部的执行流
- ==误区 2：用了线程程序就一定更快==  
  线程也有创建、调度、同步开销；如果任务太小或锁竞争严重，可能不快反慢

---

## 2. 进程和线程的区别

一句话：

> **进程是资源分配的基本单位，线程是 CPU 调度的基本单位**

| 类比    | 含义                       |
| ----- | ------------------------ |
| 进程像公司 | 拥有地址空间、文件描述符、全局资源等       |
| 线程像员工 | 共享公司资源，但有自己的**工作栈和执行现场** |

---

### 2.1 创建方式对比：`fork` vs `pthread_create`

#### `fork()`：创建新进程

```c
pid_t pid = fork();

if (pid == 0) {
    // 子进程
} else {
    // 父进程
}
```

`fork()` 的特点：

1. 创建的是**新进程**
2. 父子进程拥有各自独立的==**虚拟地址空间**==
3. 子进程初始内容来自父进程，但之后变量修改互不影响
4. 父进程通常通过 `wait()` / `waitpid()` 回收子进程

#### `pthread_create()`：创建新线程

```c
pthread_t tid;
pthread_create(&tid, NULL, thread_func, arg);
```

`pthread_create()` 的特点：

1. 创建的是**同一进程内的新线程**
2. 不会复制完整进程地址空间
3. 新线程从指定的 `thread_func` 函数开始执行
4. 多个线程共享同一进程的大部分资源
5. `joinable` 线程通常需要 `pthread_join()` 回收资源

#### 对比表

| 对比点 | `fork()` | `pthread_create()` |
|---|---|---|
| 创建对象 | 新进程 | 新线程 |
| 地址空间 | 父子进程隔离 | 同一进程内共享 |
| 全局变量 | 各自一份逻辑副本 | 共享同一份 |
| 通信方式 | 需要 IPC | 可直接访问共享数据 |
| 回收方式 | `wait()` / `waitpid()` | `pthread_join()` |
| 常见风险 | 僵尸进程 | joinable 线程未回收、数据竞争 |

> [!tip] 记忆方式
> `fork()` 是**复制一个新的进程执行环境**  
> `pthread_create()` 是**在当前进程里增加一个执行流**

---

### 2.2 重点：线程到底共享了哪些东西？

#### **线程共享的内容**

- **代码段**
- **全局变量**
- **静态变量**
- ==**堆区**==，例如 `malloc()` / `new` 分配的空间
- 文件描述符表
- 当前工作目录等进程级资源

#### 线程私有的内容

- **栈**
- **寄存器上下文**
- 程序计数器 `PC`
- 线程 ID
- 线程局部数据，例如 `errno` / TSD

#### 堆和栈一定要分清

```c
void *worker(void *arg)
{
    int local = 10;               // 当前线程自己的栈
    int *p = malloc(sizeof(int));  // 进程共享的堆

    return NULL;
}
```

| 区域 | 是否共享 | 说明 |
|---|---|---|
| 栈 `stack` | 线程私有 | 保存函数调用、局部变量、返回地址 |
| 堆 `heap` | 线程共享 | `malloc()` 分配，属于进程地址空间 |
| 全局变量 | 线程共享 | 所有线程访问同一份 |
| 寄存器 | 线程私有 | 保存当前线程执行现场 |
| 文件描述符表 | 线程共享 | 同一进程内线程共享打开文件资源 |

#### 为什么寄存器是私有的？

寄存器保存的是当前线程的执行现场，包括：

- 当前执行到哪里；
- 计算中间结果；
- 函数调用状态

线程切换时，操作系统要保存当前线程的寄存器，再恢复另一个线程的寄存器  
所以寄存器不能共享，否则线程切换回来后就不知道自己执行到哪里了

### 常见误区

| 误区 | 正确理解 |
|---|---|
| 堆栈都是私有的 | **栈私有，堆共享** |
| 寄存器是共享的 | 寄存器属于线程执行现场，是线程私有的 |
| 文件描述符是线程私有的 | 同一进程内线程共享文件描述符表 |
| 全局变量在线程中各有一份 | 全局变量属于进程资源，线程共享同一份 |

### 2.3 经典例题！

```c
for (int i = 0; i < 4; i++) {
    pthread_create(&tid[i], NULL, thread_func, &i);
}

for (int i = 0; i < THREAD_NUM; i++) {  
    pthread_join(threadId[i], NULL);  
}
```

#### 问题：4 个线程一定会拿到 `0, 1, 2, 3` 吗？

不一定

原因是：

- `pthread_create()` 传入的是 `&i`，也就是**同一个循环变量 `i` 的地址**
- 线程拿到的不是创建线程那一刻的 `i` 值
- **线程真正运行时，会再去这个地址读取当前 `i` 的值**

因此结果可能是：

- `0 0 0 0`
- `4 4 4 4`
- `0 1 2 3`
- 任意重复或乱序组合

**具体取决于调度顺序**

#### 为什么可能全部输出 `0`？

如果代码结构是：

```c
int i;

for (i = 0; i < THREAD_NUM; i++) {
    pthread_create(&threadId[i], NULL, printArgument, &i);
}

for (i = 0; i < THREAD_NUM; i++) {
    pthread_join(threadId[i], NULL);
}
```

第二个 `for` 循环也在修改同一个 `i`

可能时间线如下：

1. 主线程创建完所有线程
2. 主线程进入 `join` 循环
3. **`i` 被重新赋值为 `0`**
4. **此时子线程才真正开始读取 `*p`**
5. 它们读到同一个 `i`，当前值是 `0`
6. 所以全部输出 `0`

> [!warning] 易错点
> `pthread_join()` 不能修复传参错误  
> 它只负责**等待线程结束**和**回收线程资源**

---

#### 方法 1：数组隔离地址

```c
int args[THREAD_NUM];

for (int i = 0; i < THREAD_NUM; i++) {
    args[i] = i;
    pthread_create(&tid[i], NULL, thread_func, &args[i]);
}

for (int i = 0; i < THREAD_NUM; i++) {
    pthread_join(tid[i], NULL);
}
```

线程函数：

```c
void *thread_func(void *arg)
{
    int id = *(int *)arg;
    printf("thread id = %d\n", id);
    return NULL;
}
```

本质是：

| 线程 | 参数地址 |
|---|---|
| T0 | `&args[0]` |
| T1 | `&args[1]` |
| T2 | `&args[2]` |
| T3 | `&args[3]` |

每个线程拿到不同地址，所以不会都读同一个 `i`

> [!danger] 不要这样写
> ```c
> for (int i = 0; i < THREAD_NUM; i++) {
>     int arg = i;
>     pthread_create(&tid[i], NULL, thread_func, &arg);
> }
> ```
> `arg` 是循环内部局部变量，生命周期短，地址还可能被复用

---

#### 方法 2：`void *` 参数“携带整数值”

规范写法：

```c
#include <stdint.h>

pthread_create(&tid[i], NULL, thread_func, (void *)(intptr_t)i);
```

线程函数：

```c
void *thread_func(void *arg)
{
    int id = (int)(intptr_t)arg;
    printf("thread id = %d\n", id);
    return NULL;
}
```

注意：

> [!note]
> `void *` 不是空指针  
> `void *` 是**通用指针类型**，`NULL` 才是空指针

这种写法不是传 `i` 的地址，而是借用 `void *` 这个参数槽携带一个整数值

因此线程函数里不能写：

```c
int id = *(int *)arg;   // 错误
```

因为此时 `arg` 不是真的指向某个 `int` 的地址

#### 两种方法对比

| 方法 | 本质 | 线程函数中怎么取值 | 适合场景 |
|---|---|---|---|
| 数组隔离地址 | 每个线程拿不同地址 | `*(int *)arg` | 通用、清晰、安全 |
| `(void *)(intptr_t)i` | 用参数槽携带整数值 | `(int)(intptr_t)arg` | 只传小整数编号 |

### 我的理解

> 线程传参的核心不是看语法，而是判断：  
> ==多个线程最终是不是读同一个会变化的存储单元==

---

## 3. 线程控制：create / join / exit

线程生命周期：

1. 创建线程：`pthread_create()`
2. 线程执行：从 `start_routine` 函数开始运行
3. 等待线程结束：`pthread_join()`
4. 线程结束：`return` / `pthread_exit()`
5. 特殊情况：`pthread_cancel()`

---

### 3.1 `pthread_create()`

函数原型：

```c
#include <pthread.h>

int pthread_create(
    pthread_t *thread,
    const pthread_attr_t *attr,
    void *(*start_routine)(void *),
    void *arg
);
```

参数解释：

| 参数 | 含义 |
|---|---|
| `thread` | 保存新线程 ID |
| `attr` | 线程属性；先写 `NULL` 表示默认属性 |
| `start_routine` | 新线程从哪个函数开始执行 |
| `arg` | 传给线程函数的参数 |

最小例子：

```c
#include <stdio.h>
#include <stdint.h>
#include <pthread.h>

void *worker(void *arg)
{
    int id = (int)(intptr_t)arg;
    printf("worker thread: %d\n", id);
    return NULL;
}

int main()
{
    pthread_t tid;

    pthread_create(&tid, NULL, worker, (void *)(intptr_t)1);

    pthread_join(tid, NULL);

    return 0;
}
```

编译：

```bash
gcc main.c -o main -pthread
```

> [!tip]
> `-pthread` 不只是链接 pthread 库，还会启用线程相关的编译/链接选项

---

### 3.2 `pthread_t` 和 `pthread_self()`

`pthread_t` 是线程 ID 类型：

```c
pthread_t tid;
pthread_create(&tid, NULL, worker, NULL);
```

当前线程可以用：

```c
pthread_self();
```

获取自己的线程 ID

对比：

| 函数 | 含义 |
|---|---|
| `getpid()` | 当前进程 ID |
| `pthread_self()` | 当前线程 ID |

同一进程内多个线程：

- `getpid()` 可能一样；
- `pthread_self()` 不一样

---

### 3.3 `pthread_join()`

函数形式：

```c
int pthread_join(pthread_t thread, void **retval);
```

作用：

1. 等待指定线程结束
2. 回收 `joinable` 线程的资源
3. 可获取线程函数的返回值

类比前两章：

| 进程 | 线程 |
|---|---|
| 子进程结束后，父进程用 `wait()` / `waitpid()` 回收 | joinable 线程结束后，用 `pthread_join()` 回收 |

但不要过度类比：

> [!warning]
> 进程有父子关系；线程之间没有严格父子关系

#### 获取线程返回值

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>

void *worker(void *arg)
{
    int *result = malloc(sizeof(int));
    *result = 100;
    return result;
}

int main()
{
    pthread_t tid;
    void *ret;

    pthread_create(&tid, NULL, worker, NULL);
    pthread_join(tid, &ret);

    int *p = (int *)ret;
    printf("result = %d\n", *p);

    free(p);
    return 0;
}
```

不要这样写：

```c
void *worker(void *arg)
{
    int x = 100;
    return &x;   // 错误：返回栈上局部变量地址
}
```

原因：

- `x` 在线程函数栈上
- 线程函数结束后，该栈空间失效
- 返回它的地址会变成悬空指针

正确做法：

- 返回 `malloc()` 出来的堆空间；
- 或把结果写入主线程传入的结构体 / 数组

---

### 3.4 线程结束的几种方式

线程可以通过以下方式结束：

1. 线程函数 `return`
2. 调用 `pthread_exit()`
3. 被 `pthread_cancel()` 请求取消
4. 整个进程结束，所有线程一起结束

普通线程中：

```c
return NULL;
```

和：

```c
pthread_exit(NULL);
```

效果接近，都是结束当前线程

---

#### 主线程直接退出

看代码：

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

void *worker(void *arg)
{
    sleep(1);
    printf("worker done\n");
    return NULL;
}

int main()
{
    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);

    printf("main done\n");
    return 0;
}
```

问题：一定会输出 `worker done` 吗？

答案：**不一定**

原因：

- `main return` 通常导致整个进程结束
- 进程一结束，进程内其他线程也会被终止
- 所以 `worker` 可能还没来得及执行完

**正确改法 1**：使用 `pthread_join()`

```c
int main()
{
    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);

    printf("main done\n");

    pthread_join(tid, NULL);

    return 0;
}
```

**正确改法 2**：主线程调用 `pthread_exit()`

```c
int main()
{
    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);

    printf("main done\n");

    pthread_exit(NULL);
}
```

`pthread_exit(NULL)` 的含义：

- 只结束 `main` 线程；
- 不立即结束整个进程；
- 让其他线程继续运行

---

#### `joinable` vs `detached`

**默认线程状态是**：`PTHREAD_CREATE_JOINABLE`

特点：

- 可以被 `pthread_join()` 等待；
- 线程结束后状态保留；
- 需要其他线程 `join` 来回收资源；
- 可以通过 `join` 获取返回值

**特殊的分离线程**：`PTHREAD_CREATE_DETACHED`

特点：

- 线程结束时自动释放资源；
- **不能被 `pthread_join()`；**
- **不能获取它的返回值；**
- 适合不关心返回值的后台任务

| 状态 | 是否能 join | 结束后资源 | 是否能拿返回值 | 适合场景 |
|---|---|---|---|---|
| `joinable` | 能 | 等待 join 回收 | 能 | 需要同步、需要结果 |
| `detached` | 不能 | 自动释放 | 不能 | 不关心结果的后台任务 |

> [!warning] 注意
> `joinable` 线程如果结束后没人 `join`，可能残留线程状态信息，类似“僵尸线程”  
> `detached` 线程不能再被 `join`

## 4. 数据安全

线程共享数据带来方便，也带来风险

经典例子：

```c
#include <stdio.h>
#include <pthread.h>

int counter = 0;

void *worker(void *arg)
{
    for (int i = 0; i < 100000; i++) {
        counter++;
    }
    return NULL;
}

int main()
{
    pthread_t t1, t2;

    pthread_create(&t1, NULL, worker, NULL);
    pthread_create(&t2, NULL, worker, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    printf("counter = %d\n", counter);
    return 0;
}
```

直觉：

- 线程 1 加 `100000` 次；
- 线程 2 加 `100000` 次；
- 最终 `counter` 应该是 `200000`

实际：

> 结果可能小于 `200000`

原因：

> ==`counter++` 不是原子操作==

它大致可以拆成三步：

1. `load`：从内存读取 `counter` 到寄存器
2. `add`：寄存器中的值加 `1`
3. `store`：把结果写回内存

两个线程同时执行时可能出现：

| 时刻 | 线程 A | 线程 B | `counter` |
|---|---|---|---|
| 初始 |  |  | 10 |
| 1 | 读到 10 |  | 10 |
| 2 |  | 读到 10 | 10 |
| 3 | 计算 11 | 计算 11 | 10 |
| 4 | 写回 11 |  | 11 |
| 5 |  | 写回 11 | 11 |

理论上两次加一应该得到 `12`，实际只得到 `11`  
这叫 **lost update，丢失更新**

---

### 4.1 判断数据竞争的本质

不是“用了多线程就一定错”

判断三件事：

1. **是否访问共享数据？**
2. **是否至少有一个线程会修改共享数据？**
3. **多个访问是否可能交错执行？**

---

### 4.2 临界区 critical section

> **临界区：访问共享资源，并且需要互斥执行的代码区域**

例如：

```c
counter++;
```

如果多个线程会同时执行它，那么它就是临界区

更展开：

```c
int tmp = counter;
tmp = tmp + 1;
counter = tmp;
```

这段读-改-写整体需要被保护

---

### 4.3 互斥锁 mutex

基本写法：

```c
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&mutex);

        counter++;

        pthread_mutex_unlock(&mutex);
    }
```

只要所有线程都遵守同一把锁：

> 同一时刻最多只有一个线程能进入临界区
