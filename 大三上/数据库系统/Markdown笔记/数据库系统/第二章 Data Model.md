## 1. Schema & State
**schema** 是关系中==**属性的集合**==，描述关系的结构
- **Students(SID, Name, Age, GPA)**
**state** 是当前关系中==**实际存在的元组集合**==，描述的是数据
- 增删改查**数据**改变State，增删改查**属性**改变Schema，一个Schema不同时刻有多个State
## 2. Relation
Relation：关系表
**组成：关系名+属性+数据元组**
### Relation 的**三大特性**：
1. **行、列无序性**
2. **不允许重复行**
3. **无多值属性**

### **空值, Null Value**：
1. Null 出现的三种情况
- 值未知
- 尚未赋值
- 不适用
2. Null ≠ 0 ≠ 空格
- SQL 中：  
    **SQL 的数值计算中将 null 视为0**
    **SQL 的排序中将 null 视为很大的值**

## 3. 重点： Key 各种键

### 1. 超级键 Superkey
**定义**：一个关系的 superkey 是由可**唯一确定一行的字段的集合**
**性质**：
1. 一个关系至少有一个 SK , 即所有字段的集合
2. 包含 superkey 的集合也是 SK
3. 仅凭当前数据**不能证明某集合==一定==是 superkey**，只能判断当前情况（做题）
==**判断：只要不是一对多**==
### 2. Key / Candidate Key 候选键
定义：最小的 superkey
(1) 是超键；(2) 它是最小的，移除任何一个属性后就不再是超键

### 3. Primary Key 主键
候选键中**选出一个**作为主要标识符，主键通常选择**属性最少、最常用**的那个，**以提升存储效率和查询处理效率**
- 在关系定义时, 主键被选定, 一旦选定, 不能更换
- 主键的字段的值构成的所有 tuple 在关系表中唯一且 **==非空==**.
- 主键常用于其它关系表的引用

### 4. Foreign Key 外键
**用于建立关系之间的联系**
定义：一个关系 R1 的 **一组属性** 满足以下两个条件，则称该组属性 是 R1 中的**外键**
1. **R1 中的外键**必须对应 **R2 中的主键**，使得FK和PK拥有**相同数量**且**域兼容的属性（取值范围 + 语义一致）**
2. 对于 **R1 中的任意元组 t1**，要么存在一个元组 t2，使得 t1[FK] = t2[PK]，要么 **t1[FK] 为零元组** （**外键必须是对方表里有的，或者留空**）

==**易错：外键 需要显式地指定**==

## 4. 完整性约束
1. **实体完整性**：主键不为空
2. **参照完整性**：外键的值必须存在于被引用表的主键中，或者为 Null
3. **域约束**：属性值必须在定义的合法范围内
