## 2. 决定性 Determinancy

- **定义**：如果属性 A 的每一个值都恰好对应属性 B 的一个值（可以为空），则称 A 是 B 的决定因素  —— 这种关系表述为 “**A 决定 B**” 或“B **函数依赖**于 A”
- 例子： ==**Sno 决定了 Student Name**==

**两种决定性：**
1. **简单决定性**：单个属性即可唯一确定另一个属性的值
2. **复合决定性**：多个属性组合在一起才能确定另一个属性的值

## 3. 函数依赖 FD

- **定义**：在一个关系模式 $R(A_1, ..., A_n)$ 中，对于两个**属性子集** $X$ 和 $Y$，如果对于 $R$ 的任意两个元组 $t1$ 和 $t2$，只要 $t1[X] = t2[X]$，就一定有 $t1[Y] = t2[Y]$，那么称 **$X$ 函数决定 $Y$**（或 $Y$ 函数依赖于 $X$），记作 $X \rightarrow Y$

**等同于决定性：**
- 对于每一个 $X$ 值，都对应唯一的 $Y$ 值
- 不存在两个元组 $X$ 值相同但 $Y$ 值不同的情况

### **平凡函数依赖与非平凡函数依赖**
**非平凡的函数依赖**：X→Y，但Y⊈X
**平凡的函数依赖**：X→Y，但Y⊆X —— ==**必成立**== 
NON-Trivial FD： (Sno, Cno) → Grade
        Trivial FD ： (Sno, Cno) → Sno
                     (Sno, Cno) → Cno

### 完全函数依赖与部分函数依赖
在R(U)中，如果X→Y，并且对于X的任何一个**真子集X’**, 都有 X’ ↛ Y, 则称**Y对X完全函数依赖**，记作X → Y

若X→Y，但Y不完全函数依赖于X，则称**Y对X部分函数依赖**

## 4. 函数依赖集的闭包 ($F^+$) 与 Armstrong 公理

- **定义**：**$F^+$** 从给定的 **FD 集合** $F$ 出发，利用==**推理规则**==可以推导出的**所有**可能的 FD 集合
—— ==**所有成立的规则**==

- **Armstrong 公理 (推理规则)** ：==**最基本的三条规律**==
	- **自反律**：如果 $Y \subseteq X$，则 $X \rightarrow Y$
	- **扩充律**：如果 $X \rightarrow Y$，则 $XZ \rightarrow YZ$
	- **传递律**：如果 $X \rightarrow Y$ 且 $Y \rightarrow Z$，则 $X \rightarrow Z$

**引申规则**：
- **分解规则**：如果 $X \rightarrow YZ$，则 $X \rightarrow Y$ 且 $X \rightarrow Z$。
- **合并规则**：如果 $X \rightarrow Y$ 且 $X \rightarrow Z$，则 $X \rightarrow YZ$。
- **伪传递规则**：如果 $X \rightarrow Y$ 且 $WY \rightarrow Z$，则 $WX \rightarrow Z$

**习题思路**：
- 题目给出一组 FD，求F+，**实际就是问能否推导出某个新的 FD**
- **解法**：灵活运用上述三条公理和三条引申规则进行推导

## 5. 属性闭包 ($X^+$) 及其计算算法
$F^+$ 是“规则”的集合，$X^+$ 是“属性”的集合
**$X^+$ (比如求 $A^+$)**：我们算 $A$ 能决定哪些列。$A \rightarrow B, B \rightarrow C \implies A \rightarrow C$。所以 **$A^+ = \{A, B, C\}$，这是一个属性列表

- **定义**：在给定 FD 集合 $F$ 下，属性集 $X$ 能够==**函数决定**==的**所有属性的集合**

- **重要性**：计算 $X^+$ 是判断 $X$ 是否为超键（SuperKey）或候选键（Candidate Key）的基础

### **计算算法 —— 考点**

- 初始化：$X^+ = X$
    
- 循环遍历 $F$ 中的每个 $FD (U \rightarrow V)$：
    
    - 如果 $U \subseteq X^+$，则 $X^+ = X^+ \cup V$。
        
- 重复步骤 2，直到 $X^+$ 不再变化

**==PPT 例子 (详细步骤)==** ：

- **题目**：$R(A, B, C, G, H, I)$，$F = \{ A \rightarrow B, CG \rightarrow HI, B \rightarrow H, A \rightarrow C \}$。求 $(AG)^+$。
    
- **过程**：
    
    1. **初始化**：$result = AG$。
        
    2. **第一轮遍历**：
        
        - $A \rightarrow B$：$A$ 在 $result$ 中，加入 $B$。$result = ABG$。
            
        - $CG \rightarrow HI$：$C$ 不在 $result$ 中（此时只有 $G$），跳过。
            
        - $B \rightarrow H$：$B$ 在 $result$ 中，加入 $H$。$result = ABGH$。
            
        - $A \rightarrow C$：$A$ 在 $result$ 中，加入 $C$。$result = ABCGH$。
            
    3. **第二轮遍历**（因为 $result$ 变了）：
        
        - $CG \rightarrow HI$：现在 $C$ 和 $G$ 都在 $result$ 中了！加入 $H, I$。$result = ABCGHI$。
            
    4. **结果**：$(AG)^+ = ABCGHI$

==**定理**==：
- ==**超键 (SuperKey)**：如果 $X^+ = R$（包含所有属性），则 $X$ 是超键==
    
- **候选键 (Candidate Key)**：最小的超键（没有任何真子集是超键）

## 6. 寻找Candidate key
- **方法 1 (试探法)**：对每个属性子集==**计算闭包**==，看是否包含所有属性

- **方法 2 (图论/分类法 - 更高效)** ：
    1. 画出依赖图，有向图 比如 A --> B
        
    - **$V_{ni}$ (Only Incoming)**：==**出度=0的属性，一定不包含在任何候选键中**==
        
    - **$V_{no}$ (Only Outgoing / No Incoming)**：出度=0（**或没出现**）的属性，**一定包含在所有候选键中**
        
    - **$V_{bi}$ (Both)**：既在左边也在右边出现的属性。**可能**在候选键中
        
    - **算法**：
        
        1. 先算 $V_{no}^+$：如果包含全集，那 $V_{no}$ 就是唯一的候选键
            
        2. 如果不包含，就尝试将 $V_{no}$ 与 $V_{bi}$ 中的属性组合，计算闭包，直到找到所有能推导出全集的最小组合

- **PPT 例子**：
    
    - **例 1**：$R(A, B, C, G, H, I)$, $F = \{ A \rightarrow BC, CG \rightarrow HI, B \rightarrow H \}$ 
        
        - $V_{no} = \{ A, G \}$（只在左边）
            
        - $V_{ni} = \{ H, I \}$（只在右边）
            
        - 计算 $(AG)^+$：
            
            - $A \rightarrow BC \implies ABCG$。
                
            - $B \rightarrow H \implies ABCGH$。
                
            - $CG \rightarrow HI \implies ABCGHI$。
                
        - 因为 $(AG)^+$ 包含全集，且 $A, G$ 必须在键中，所以 **$AG$ 是唯一的候选键**。
            
    - **例 2**：$R(A, B, C, D, E, H)$, $F = \{ A \rightarrow B, AB \rightarrow E, BH \rightarrow C, C \rightarrow D, D \rightarrow A \}$ 23。
        
        - $V_{no} = \{ H \}$。
            
        - $V_{ni} = \{ E \}$。
            
        - $V_{bi} = \{ A, B, C, D \}$。
            
        - $H$ 必须在键中，$E$ 一定不在
            
        - 尝试 $H$ 结合其他属性：
            
            - $(AH)^+ \rightarrow ... \rightarrow ABCDEH$ (是候选键)
                
            - $(BH)^+ \rightarrow ... \rightarrow ABCDEH$ (是候选键)
                
            - $(CH)^+ \rightarrow ... \rightarrow ABCDEH$ (是候选键)
                
            - $(DH)^+ \rightarrow ... \rightarrow ABCDEH$ (是候选键)
                
        - 结果：$AH, BH, CH, DH$ 都是候选键

- **习题思路**：
    - 给定 $R$ 和 $F$，找出所有的候选键
    - **技巧**：先找“必须有”的属性（只出现在左边），算闭包；如果不够，再尝试加“可能有”的属性（两边都出现）

## 7. 关系分解：无损连接与保持依赖
关系分解：

**无损连接 (Lossless Join)**：分解后的表 $R1, R2$ 自然连接后，==**能够还原**==回原来的表 $R$，**没有信息丢失或产生多余元组**

- **判定定理**：分解 $\{R1, R2\}$ 是无损的，当且仅当 $(R1 \cap R2) \rightarrow (R1 - R2)$ **或者** $(R1 \cap R2) \rightarrow (R2 - R1)$。即：**==两个表的公共属性必须是其中一个表的超键==**

**例子：**
- **无损判定例 1**：$R(A, B, C, D, E)$, $F = \{ A \rightarrow BC, CD \rightarrow E, B \rightarrow D, E \rightarrow A \}$。分解为 $R1(A, B, C), R2(A, D, E)$ 
    
    - **公共属性**：$R1 \cap R2 = \{ A \}$
        
    - 检查 $A$ 是否能决定 $R1$ ==**或**== $R2$ 的其他属性：
        
        - 在 $R1$ 中：$A \rightarrow BC$ (已知)，所以 $A \rightarrow ABC$，$A$ 是 $R1$ 的超键
            
    - 结论：**无损连接**
        
- **无损判定例 2**：同上 $R$ 和 $F$，分解为 $Ra(A, B, C), Rb(C, D, E)$ 
    
    - 公共属性：$Ra \cap Rb = \{ C \}$
        
    - 检查 $C$：
        
        - $C^+$ 在 $F$ 下能推导出什么？只有 $C$ 自己（如果不结合 $D$ 推不出 $E$）
            
        - $C \rightarrow AB$？否。
            
        - $C \rightarrow DE$？否。
            
    - 结论：**有损连接** 

**依赖保留**：原有的所有 FD 在==**分解后的表**==中**仍然能够被推导出来**（不需要跨表Join就能检查约束）

==**习题思路：**==
- **题型 1**：给分解方案，问是否无损
    
    - **解法**：找公共属性，算公共属性的闭包，看它能不能覆盖分解出的任意一张表的所有属性
        
- **题型 2**：给分解方案，问是否保持依赖
    
    - **解法**：看 $F$ 中的每个 FD $X \rightarrow Y$。
        
        - 如果 $X$ 和 $Y$ 都在同一个分解表中，则保留。
            
        - 如果跨表了，看能不能通过其他保留下来的 FD 推导出来
