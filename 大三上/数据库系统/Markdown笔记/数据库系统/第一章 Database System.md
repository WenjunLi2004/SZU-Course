## 1. 文件系统的问题
**应用程序 + 独立文件**
**浓缩：**
1. **孤 —— 数据是分散孤立的，不通用，缺乏统一管理**
2. **独 —— 应用依赖于数据的定义，修改麻烦，视图单一**
3. **冗—— 数据冗余，不一致，不保证不备份不丢失**
4. **难—— 访问和控制困难，查询语言，高效查询，并发控制，多访问控制**
### **DB 的优点**

1. 通用，共享数据
2. 适应数据的结构改变，表示数据间的复杂关系，不同用户不同视图
3. 控制数据冗余，保证数据完整性，备份和还原，保证最新信息的可用性
4. 提供数据的访问控制，并发控制，减少应用开发时间，降本增效

==**上面两个难用在：查询复杂，结构僵化**==
**关系型数据库 RDBS：关系表**

## 3. 数据库系统三件套
**(1) 产生原因**: 数据逐渐增多, 需要存储和处理技术.

==**(2) 组成**==: 数据库 + 数据模型 + 管理数据库的软件

① **[Database]** ：有如下**三条性质的==数据的集合==**:
- (i) 对应现实中的某些方面.
- (ii) 因特殊要求而创建
- **(iii) 数据间相关**

② [Data Model] ：**对数据的描述**
**(i) 结构**
**(ii) 操作**
**(iii) 约束**

③ [DBMS]：用于**定义(define)、存储(store)、操作(manipulate)和控制(control)** 数据的软件
- 定义：定义数据的类型，结构和约束
- 存储：存储以支持高效访问
- 操作：用查询语言检索与更新
- 控制：访问控制

## 4. 数据库语言：DDL / DML / DCL
(1) [Data Definition Language, DDL]：**定义模式(schema)**.

(2) [Data Manipulation Language, DML] ：**对数据进行增删改查**

	① [Query Language] DML中用于查询数据的部分
	
	② 分类:
	
	(i) [Procedural DML] 用户需同时知道需要什么数据和如何得到它.
	
	难用, 但是效率高.
	
	(ii) [Non-procedural DML] 用户只需知道需要什么数据. 例: SQL.
	
	好用, 但是效率低.
	
	③ 解决办法: Non-procedural DML + query optimization.

(3) [Data Control Language, DCL] 对 DB 进行权限控制

- **SQL语言三种语言都包含到**

## 5. 数据库模式 Schema
- 定义：对用户数据的描述
- **在关系模型中, 一个 DB Schema = 一系列的表**

### DBMS 三层模式结构 -- Schema分类
1. **最外层：外模式**：**用户看到的数据视图**，通过特定的程序或查询展现
    
- **中间层：概念模式 (Conceptual Schema)**：描**述了数据库中所有的数据以及它们之间的关系**，但不涉及具体的存储细节
    
- **最内层：内模式 (Internal / Physical Schema)**：描述数据在==**物理介质上实际上是如何存储的**==（如字节偏移量、索引等）
